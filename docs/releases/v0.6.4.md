# v0.6.4

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.3](./v0.6.3.md)：多会话落库按会话切开；跨块的词落库后仍能搜到；忙时换徽章或工作目录不拆掉这一轮；模型路线的并发上限在同时换模型时守住；表情球在流式负载下跟着转；子代理被停时父会话收到原因、已跑的进度和恢复办法；截断的回合自动续写与步内重试的额度上调，续写的「继续」在对话里显示成一条真实用户消息；每个模型可以单独设同时会话数。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.4`。

Relative to [v0.6.3](./v0.6.3.md): durable writes are per session; a word split across chunks stays searchable after commit; changing the badge or working directory mid-turn no longer tears that turn down; the per-route model cap holds under a concurrent switch; the presence ball keeps turning under stream load; a stopped child tells its parent why, how far it got, and how to resume; a truncated turn gets more auto-continue and in-step retry budget, and its 「继续」 shows up as a real user message; a single model can set its own live-session ceiling. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.4`.

### 完善

* **多会话落库按会话切开**：一个会话的用户消息、轮次边界，或它自己堆到 64 条，只提交这一份。旁边还在流式输出的会话留在内存里，不会被这次提交一起写盘。
* **软预算设置进循环**：触发比例、压缩后保留上限、额外减半次数从 Settings 读进自动压缩。`agent-loop` 模式上的字段在 Host 或 Face 都有读取点。
* **表情球在流式负载下跟着转**：同一段墙钟里，姿态更新从旧的约 12 帧逻辑的 47 次提高到 240 次（5.11 倍）。墙钟同为约 480ms。
* **模型列表可刷新**：Settings「刷新列表」只核对当前已配置的模型——上游没有的删掉，仍在的更新思考档位，手填显示名称不动。获取可用模型仍只负责勾选添加。
* **拉取可用模型带上思考档位**：OpenAI 兼容目录里的 `reasoning`（含 OFM `default`）进入发现结果与新采纳行。
* **子代理被停时，父会话收到交代**：取消、接管或打断一个可续子代理，不再只是静默抑制「已结束」提示——父会话收到一条说明：谁停的（用户 / 父会话 / 接管）、已经跑了多少步、产出过多少条工具结果、这一轮里自动发过几次「继续」，以及怎么接着让它跑（`send_message` / `followup_task`）。非正常结束（到输出上限、被中断、报错）一定会唤醒空闲的父会话，正常收尾仍走共用的自动唤醒额度。同一条主线上别的会话也能收到「这轮被停」的提示。
* **截断的回合自动续写更多、步内重试更多**：一轮内自动续写的上限定为 10（原 4），一步内 LLM 重试默认 30（原 8）。自动续写发出的「继续」现在是一条真实用户消息——在对话里按用户消息显示，有来源标记 `auto-continue`，不再是灰色提示条；达到输出上限的提示会说明本轮已经自动续写过几次，以及是不是因为自动续写关着才停在这里。
* **每个模型可以单独设同时会话数**：模型行新增可选的 `maxConcurrentSessions`（整数 1–64，留空就用 Agent loop 的全局上限）。「刷新列表」除了核对已配置模型，还会把上游披露、而这一行留空的能力值（上下文窗口、输出上限、软预算）补上，并刷新思考档位；手填的数字和显示名称不动。

### 修复

* **跨块的词落库后仍能搜到**：流式文本按块进全文索引。一个词切在两块上时，待写队列里能拼上，提交或会话被逐出内存之后以前会消失。现在每次提交额外写入拼好的文本。
* **忙着说话时换徽章或工作目录，不拆掉这一轮**：和 v0.6.3 对设置变更的处理一样，会话还在跑或还在收尾时先记下重建，空闲后再换代理。空闲会话仍然马上重建。
* **模型路线的并发上限在同时换模型时守住**：12 个正在跑的会话挤向一条上限为 3 的路线，只放进 3 个，其余 9 个留在原路线。父会话换模型不改已经派出去的子会话钉选。

## 用户侧复杂情况

从使用方式列出容易踩到的路径。覆盖状态以本工作树的自动化测试为准。

| 用户行为 | 风险 | 本工作树 | 覆盖 |
| --- | --- | --- | --- |
| 多个会话同时流式输出，其中一个刚发出消息 | 一次落库把旁路会话也写盘，拖慢或互相干扰 | 只提交触发的会话 | 已测：24 会话隔离落库 |
| 流式文本还没落盘就搜索，或落库后再开库搜索 | 切在两块上的词搜不到 | 待写队列拼接；提交再写一条拼好的索引 | 已测：跨块词重开仍命中 |

| 回合进行中切换模型 | 误伤其它会话或拆掉本轮 | 按会话热切换，不写全局默认、不触发全员重建 | 已有路径；并发上限已压测 |
| 许多会话同时挤向同一条模型路线 | 超过 `maxConcurrentModelSessions` | 换路线同样占位，满员拒绝 | 已测：12→上限 3，放进 3 / 拒绝 9 |
| 父会话换模型，子会话还在跑 | 子会话跟着漂到新模型 | 派出时钉选，父会话变更不改写 | 已测：父切路线后子钉不变 |
| Settings 里钉了 `subagentModel`，工具参数又自带模型 | 优先级错乱 | 工具参数 → 舰队设置 → 父钉选 | 已有路由单测 |

## 验证

* 两个会话同时流式输出时，只在其中一个发送用户消息，另一个会话的文本块不应马上出现在 `sessions.db`。
* 一个词拆在相邻两块文本上，搜索在落库前和重开后都能找到该会话。
* 模型并发打满时，再把别的正在跑的会话换到这条路线会被拒绝；已经派出的子会话不跟着父会话改模型。
* 回合还在输出时更换徽章，这一轮继续；结束后下一次才用新徽章。

### Improved

* **Durable writes are per session**: a user message, a turn edge, or that session’s own 64-event ceiling commits only that session. A neighbor still streaming stays in memory and is not written by this commit.
* **Soft-budget settings reach the loop**: trigger ratio, post-compact recent cap, and extra halving passes are read from Settings. Every `agent-loop` schema field has a reader in Host or Face.
* **The presence ball keeps turning under stream load**: in the same wall clock, pose updates move from 47 under the old ~12fps skip to 240 (5.11×). Wall time stays about 480ms.
* **Model list refresh**: Settings **Refresh list** only checks models already configured—drops ids the provider no longer offers, refreshes thinking levels, leaves hand-edited display names alone. **Fetch available models** still only adds after the user picks.
* **Discover keeps thinking menus**: OpenAI-compatible `/models` `reasoning` (including OFM `default`) reaches discovery and newly adopted rows.
* **A stopped child tells its parent what happened**: cancelling, taking over, or interrupting a continuable child no longer just suppresses the idle notice — the parent is steered a note naming who stopped it (user / parent / takeover), how many steps and tool results it had already spent, how many times it auto-sent 「继续」 within the turn, and how to resume it (`send_message` / `followup_task`). An unexpected end (output cap, abort, error) always wakes an idle parent; a clean finish stays under the shared auto-wake budget. Other sessions on the same 主线 are told that this turn was cut off.
* **A truncated turn continues and retries further**: the within-turn auto-continue cap is 10 (was 4) and the in-step LLM retry default is 30 (was 8). The auto-continue 「继续」 is now a real user message — shown as a user message in the transcript, tagged with source `auto-continue`, no longer a grey strip. The output-cap notice says how many times the turn already auto-continued, or whether it stopped because that is switched off.
* **A single model can set its own live-session ceiling**: a model row takes an optional `maxConcurrentSessions` (integer 1–64; blank uses the Agent-loop global). **Refresh list** now also fills a capacity the provider disclosed but the row left blank (context window, output cap, soft budget) and refreshes the thinking menu, without touching hand-set numbers or display names.

### Fixed

* **A word split across chunks stays searchable after commit**: streamed text is indexed per chunk. A token cut in two was visible in the pending queue and disappeared once the batch committed or the session left memory. Each commit now also indexes the joined text.
* **Changing the badge or working directory during a turn does not tear that turn down**: same rule as the v0.6.3 settings change. A session that is running or still draining is rebuilt after it goes idle. An idle session still rebuilds immediately.
* **The per-route model cap holds when many sessions switch at once**: 12 live sessions moving onto a route capped at 3 admit 3 and leave 9 on the old route. A parent model switch does not rewrite a child pin.

## Complex situations (user view)

Paths users actually hit. Coverage is this working tree’s automation only.

| User action | Risk | This tree | Coverage |
| --- | --- | --- | --- |
| Several sessions stream; one of them just sent a message | One flush writes every neighbor | Only the triggering session commits | Measured: 24-session isolated flush |
| Search while text is still pending, or after reopen | A word split across chunks disappears | Pending join + joined index on commit | Measured: cross-chunk hit after reopen |
| A session is evicted from the resident cache | Eviction flushes other sessions; search misses pending text | Eviction flushes only the victim; search reads pending | Measured: isolated flush + pending search |
| Switch model mid-turn | Other sessions remount or this turn dies | Per-session hot route; no global default rewrite | Existing path; concurrency stress added |
| Many live sessions switch onto one popular model | Over `maxConcurrentModelSessions` | Route switch takes a slot and refuses when full | Measured: 12→cap 3 admits 3 / refuses 9 |
| Parent changes model while a child is still running | Child drifts onto the new model | Pin at spawn; parent rewrite does not touch the child | Measured: child pin survives parent switch |
| Fleet `subagentModel` set and the tool args also name a model | Wrong precedence | Tool args → fleet setting → parent pin | Existing route unit tests |
| Change badge or working directory mid-turn | Immediate dispose looks like Stop | Defer rebuild until idle | Measured: deferred set vs immediate rebuild |
| Change permission preset / extra writable roots mid-turn | Gate for this turn disagrees with the next | Roots are live getters; badge defer is separate | Readers wired; live permission has its own tests |
| Many deferred MCP tools priced into soft budget | Unexpanded schemas inflate the estimate | With `tool_search`, unexpanded stay out | Measured: disclosed &lt; 8k, dump-all &gt; 50k |
| Long chat near soft budget; Settings change trigger / keep / peel | Settings written but unused | Host reads them into compaction options; a trigger below the soft ceiling compacts first | Field wiring measured; trigger ratio 0.1 with ceiling 500 auto-compacts first |
| Agent collab (parent waits, child fails, worktree isolation) | Half-made child holds quota; parent stop hurts child | Failed spawn discards; child model pinned at spawn | Partial; discard path exists separately |
| Xiangyang / IM orchestration badge change | Tool surface must not leave the locked preset | Space badge locked; RPC rejects | Existing lock tests |
| Presence ball turns, wears glasses, bounce-click | Flat crown; glasses ignore yaw; halo vanishes | Mount fills the stage; stickers follow eyes; bounce headroom | Measured: pose 5.11×, glasses/halo cases |

Not fully pressure-tested here: full Xiangyang/IM orchestration, search after archive restore, permission chip plus Settings at once, and multi-session wall clock against a live provider. Those stay out of the “Measured” column.

## Pressure comparison

The table is one `vitest` run on this working tree on 2026-10-18 (9 files, 52 tests passed). The baseline is behavior shipped in v0.6.3, not a wall-clock race between two installers.

| What you are doing | v0.6.3 | This tree | Measured |
| --- | --- | --- | --- |
| Several sessions stream; one of them just sent a message | A durability edge committed every session in the queue | Only the session that tripped the edge is committed | 24 sessions × 63 text chunks; after the edge only the sender has rows on disk. That case took 308ms |
| Search for a word split across two chunks before flush, then reopen the store | The pending queue could join the chunks; the index after commit could not | The commit writes the joined text, so reopen still hits | 24-session case: after reopen all 24 sessions match the word |
| A word is cut exactly on a flush boundary (end of one batch, start of the next), then the session is archived and restored | Each batch is indexed alone, so the span matches neither | The next batch’s index includes the previous committed text chunk; archive copies that row | Hit after the second half is appended; still a hit after archive and restore |
| Twelve live sessions switch onto one popular model | The cap existed; parallel admits had a unit test | A route switch takes a slot and refuses when full | Cap 3: 3 admitted, 9 refused; occupancy on the two routes is 3 and 9 |
| A child is still running and the parent changes model | The child is pinned at spawn | The parent’s new route does not rewrite the child | After the parent moves, the child keeps the spawn model; the old route occupancy is 0 |
| Change the badge or folder while the turn is still talking | Settings changes wait; a badge change disposed the agent immediately | Badge and folder wait for the turn as well | Busy or draining sessions are only deferred; an idle session rebuilds at once |
| Many deferred MCP tools, soft budget priced on the request | Deferred schemas could be priced in full | With `tool_search`, unexpanded deferred tools stay out of the estimate | Gate: disclosed estimate &lt; 8,000, dump-all &gt; 50,000, and disclosed ≤ half of dump-all. The case passed, so the dump path is more than 6× the disclosed ceiling (50,000 / 8,000) |
| The presence ball turns and looks around during a stream | Lite mode could skip pose at about 12fps | Pose is composed every frame | 240 vs 47 paints, ratio 5.11; wall 481ms vs 482ms |

Every `agent-loop` field (parallel tools, step cap, max-token continue, tool order, serial/parallel settle, in-step retries, compaction strategy, trigger percent, recent cap, peel passes, inline tool-result cap, model concurrency, subagent model) has a reader in Host or Face. Permission `defaultPreset` and `extraWritableRoots` do too.

This note does not collapse the kernel into one “twice as fast” figure. Each row is that path’s own ratio or count.

## Verify

* With two sessions streaming, send a user message on only one. The other session’s chunks should not appear in `sessions.db` yet.
* A word split across two adjacent text chunks is found before commit and after reopen.
* When a model route is full, moving another live session onto it is refused. A spawned child does not follow a later parent model change.
* Changing the badge while a turn is still producing leaves that turn running. The next turn uses the new badge.
