# v0.5.27

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.5.26](./v0.5.26.md)：主会话有了自己的工作目录——模型可以读它、切它，也可以为自己开一个 linked worktree；插件有了自己的会话记录面（`plugin/record`）；沙箱不再放过「按名字屠杀 node」这类会连带打死 Host 的命令。

Relative to [v0.5.26](./v0.5.26.md): the main session now owns a working directory — the model can read it, change it, and open a linked worktree for itself; plugins get their own session-record surface (`plugin/record`); the sandbox no longer lets through “kill node by name” commands that take the Host down with them.

### 新增

* **模型工具 `working_directory`（默认注册）**：读 `{}` 返回当前 cwd，传 `{ cd }` 切换。相对路径按当前 cwd 解析，目标必须是已存在的目录；切换会重新解析工作区挂载，失败时回滚到原 cwd。并发切换按会话串行化。
* **协议事件 `working-directory/change`**：记录切换后的有效 cwd，仅落日志（不参与消息派生）。项目锚点（工作区成员身份 / 创建时根目录）与「当前有效 cwd」从此分开记录。
* **模型工具 `create_worktree`（实验，默认关闭）**：挂在 `git-worktrees` 进程插件下，在 `.xrk/worktrees/<name>` 分配 linked checkout 并进入它。复用子代理的 worktree 装配，不带 Teams 租约 / 合回登记——要回去用 `working_directory`。
* **Face RPC `session.setWorkingDirectory` 与 `worktree.create`**：客户端与模型走同一条路径；`worktree.create` 创建成功后自动进入新 checkout。
* **协议事件 `plugin/record` + `appendPluginRecord` / `pluginRecordsOf`**：插件自有的会话状态，闭集类型（不是开放式 `plugin:*`）。落日志、对模型不可见，键名校验为小写斜杠分段，载荷写入时冻结为 JSON 快照。
* **插件页 Creator 入口**：设置 → 插件页新增「让 Agent 创建插件」按钮，经 `creator-draft-bridge` 跨插件钩子调起创作会话，未打开工作区时给出明确提示。

### 修复

* **修复 sandbox 放过「按名字屠杀 node」**：`Stop-Process -Name node`、`Get-Process node | Stop-Process`、`taskkill /IM node.exe`、`killall/pkill node`、`wmic process … terminate` 现在在硬线层被拒。精确的 `Stop-Process -Id <pid>` / `taskkill /PID <n>` 仍然放行。
* **修复硬线层绕过**：检查面扩到 `pwsh` / `powershell` 工具，并新增扫描 `terminal_send` 的正文——往活着的 PTY 里敲字同样会被拦。
* **修复 Auto 审核漏判同类命令**：`classifyAutoReviewHeuristic` 加同款 node 屠杀正则作为第二道地板。
* **修复 worktree checkout 触发仓库 filter**：`--no-checkout` + hard reset，并用 `GIT_CONFIG_*` 清掉每个已配置 filter driver 的 `clean` / `smudge` / `process` / `required`，不 rewrite `.git/config`。spawn 与 `resolveAgent` 会 ensure cwd。
* **修复插件热重载复用旧模块**：Vite fallback 导入路径丢了 `?mtime=` 查询串，裸绝对路径会命中首次导入的缓存，破坏 reloadIds 与软禁用重挂测试。现在保留查询串。

### 完善

* **完善 max-tokens 自动续跑**：`autoContinueOnMaxTokens` / `autoContinueMaxRounds` 从 Face 组装选项一路透传到 `createAgent`，达到输出上限时注入一次合成的「继续」并保持回合打开。
* **完善工具行的准备态**：参数尚未流出时用 Host `presentCall` 的标题占位（原先一律留空，只剩跑动扫光），参数到达后照常显示命令 / 路径，不引入 phase 状态机。
* **完善 Status 的 cwd 展示**：优先用 `~` 缩写家目录，其次显示末两段（`…\a\b`），完整路径留在 title 属性里。
* **完善可选插件默认关闭**：`git-worktrees` 首次被发现时软禁用一次，用户在设置里启用后由 `.xrk-optional-defaults-seeded.json` 记种子，不会被再次关掉。
* **完善会话能力输出**：`formatSessionCapability` 增加 `cwd:` 一行。
* **完善文档**：Status 表新增主会话 cwd / `create_worktree` / `plugin/record` 条目（中英双语），并补上对照 DSH alpha.1 / alpha.2 的 P2 缺口清单（`--public-url`、工作步骤收起时机、三路字体、YAML frontmatter 字段列表、DevTools 组合包、Claude Code Mods 兼容层、语音设备选择、自动标题保留策略）。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.5.27`**（接管 npm `@latest`）；npmjs 保留 **0.5.27** 与回退钉 **0.3.11**。
* Desktop 私有壳版本对齐 **0.5.27**；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。

---

### Added

* Model tool **`working_directory`** (registered by default): `{}` reads the current cwd, `{ cd }` changes it. Relative paths resolve against the current cwd and the target must be an existing directory; a change re-resolves the workspace attachment and rolls back to the previous cwd on failure. Concurrent changes serialize per session.
* Protocol event **`working-directory/change`**: records the effective cwd after a successful change, log-only (not part of message derivation). The immutable project anchor (workspace membership / create-time root) and the effective cwd are now recorded separately.
* Model tool **`create_worktree`** (experimental, off by default): shipped by the `git-worktrees` process plugin, allocates a linked checkout under `.xrk/worktrees/<name>` and enters it. It reuses the subagent worktree assembly without a Teams lease / merge registry — leave via `working_directory`.
* Face RPCs **`session.setWorkingDirectory`** and **`worktree.create`**: client and model share one path; `worktree.create` enters the new checkout on success.
* Protocol event **`plugin/record`** plus **`appendPluginRecord` / `pluginRecordsOf`**: plugin-owned session state as a closed union (not the open `plugin:*` shape). Log-only and invisible to the model; keys are validated as lowercase slash-separated segments and payloads are frozen as a JSON snapshot at append.
* Plugins-page Creator entry: a “Have the Agent create a plugin” button in Settings → Plugins calls the creator session through the cross-plugin `creator-draft-bridge` hook, with an explicit message when no workspace is open.

### Fixed

* The sandbox let “massacre node by name” through: `Stop-Process -Name node`, `Get-Process node | Stop-Process`, `taskkill /IM node.exe`, `killall` / `pkill node`, and `wmic process … terminate` are now denied at the hardline floor. Precise `Stop-Process -Id <pid>` / `taskkill /PID <n>` stay allowed.
* Hardline bypass: the floor now covers the `pwsh` / `powershell` tools and scans `terminal_send` text, so typing the same command into a live PTY is caught too.
* Auto review missed the same commands: `classifyAutoReviewHeuristic` gained the matching node-massacre regex as a second floor.
* Worktree checkouts could trigger repository filters: `--no-checkout` plus a hard reset, with `GIT_CONFIG_*` clearing `clean` / `smudge` / `process` / `required` for every configured filter driver without rewriting `.git/config`. Spawn and `resolveAgent` ensure the cwd.
* Plugin hot reload reused the stale module: the Vite fallback import dropped the `?mtime=` query, and a bare absolute path hit the first import’s cache, breaking reloadIds and the soft-disable remount tests. The query string is now preserved.

### Improved

* Max-tokens auto-continue: `autoContinueOnMaxTokens` / `autoContinueMaxRounds` forward from the Face composition options all the way into `createAgent`, injecting a synthetic “continue” and keeping the turn open at the output cap.
* Tool-row preparing state: while arguments have not streamed in, the row shows the Host `presentCall` title instead of nothing but the running sweep; once arguments arrive it shows the command / path as usual, with no phase state machine.
* Status cwd display: `~`-abbreviated home paths first, otherwise the last two segments (`…\a\b`), with the full path kept in the title attribute.
* Optional plugins default off: `git-worktrees` is soft-disabled the first time it is discovered; once enabled in Settings, `.xrk-optional-defaults-seeded.json` records the seed so it is never disabled again.
* Session capability output: `formatSessionCapability` gained a `cwd:` line.
* Documentation: the Status tables gained a main-session cwd / `create_worktree` / `plugin/record` entry (zh + en) and a P2 gap list against DSH alpha.1 / alpha.2 (`--public-url`, work-step collapse timing, three-way fonts, YAML frontmatter field list, DevTools bundle, Claude Code Mods compat layer, voice device selection, automatic-title retention).

## Verify

* Ask the model for the current working directory: it returns the effective cwd.
* Ask it to change into an existing subdirectory: success; into a missing one: an explicit error with the cwd unchanged.
* Enable `git-worktrees` in Settings → Plugins and have the model open a worktree: the directory appears under `.xrk/worktrees/<name>` and the session enters it; `working_directory` returns to the original directory.
* Try `Stop-Process -Name node`: denied by the hardline floor; `Stop-Process -Id <pid>` still runs.
* `appendPluginRecord` from a plugin: the record lands in the session log and the model does not see it.
* Click “Have the Agent create a plugin” in Settings → Plugins: a creator session starts when a workspace is open, otherwise you get a message.
* A turn hits the model token cap: it resumes automatically instead of truncating.
