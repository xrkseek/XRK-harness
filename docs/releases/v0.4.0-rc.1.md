# v0.4.0-rc.1

> **读者 / Audience**：终端用户 · 插件与集成者（发行说明）

相对 [v0.3.11](./v0.3.11.md)：XRK 从「能写代码的终端 Agent」扩到能操作浏览器与桌面、能被编辑器接入、能定时自跑、能生成图像/视频/语音。`0.4.x` 是**预览线**，npm `@latest` 仍指向 v0.3.11。

Relative to [v0.3.11](./v0.3.11.md): XRK widens from a code-writing terminal agent to one that drives browsers and the desktop, plugs into editors as an ACP server, runs on a schedule, and generates images / video / voice. `0.4.x` is the **preview line** — `@latest` still points at v0.3.11.

---

## 新增 / Added

**浏览器与桌面**

* 新增交互式浏览器工具 `browser_open` / `browser_snapshot` / `browser_act` / `browser_vision`：默认 HTTP 快照并以 `@eN` 定位元素，配置 `XRK_BROWSER_CDP_URL` 后走 Chrome DevTools；`browser_vision` 截图进附件，取不到图形浏览器直接失败而非静默降级
* 新增桌面 `computer_use`：`XRK_COMPUTER_USE=1` 开启，`XRK_COMPUTER_USE_BACKGROUND` 允许后台操作，不抢占用户鼠标

**媒体与语音**

* 新增 `image_generate` 与 `video_generate`：`XRK_IMAGE_GEN*` / `XRK_VIDEO_GEN*` 指向任一 OpenAI 兼容网关即可用
* 新增语音三件套 `voice_session` / `voice_transcribe` / `text_to_speech`（`XRK_VOICE*`），并打通浏览器麦克风到 Host 的实时上行

**会话与记忆**

* 新增回合回退的工作区文件快照：回退到某一回合时，把该回合改动过的文件一并还原
* 新增策展记忆 `memory`：跨会话写入与召回，落在产品 home（`~/.xrk`），不写工作区
* 新增会话遥测：`XRK_TELEMETRY=1` 配 `XRK_TELEMETRY_OTLP_ENDPOINT` 导出 OTLP

**运行方式**

* 新增定时任务 `cronjob`（`XRK_CRON`）：到点自动开一个会话执行 prompt，可查询 / 停止 / 修改；cron 触发的回合内不再暴露 cron 工具，避免自我调度
* 新增多沙箱后端 `createSandboxStack`：`workspace`（默认）· `docker` · `bwrap` · **`windows`**（Codex 式 helper 二进制；`XRK_SANDBOX_WINDOWS_HELPER` 未配置时**失败关闭**；模式 `workspace-write` / `read-only` / `danger-full-access`）
* 新增 Agent Teams 角色编排，可按角色拆分一支子代理的分工

**接入**

* 新增 ACP 服务端 `xrkh acp`：编辑器经 stdio 直接驱动本进程，stdout 只走 JSON-RPC，诊断进 stderr
* 新增外部 Agent 运行时委托：`XRK_CLAUDE_CODE` / `XRK_CODEX_APP_SERVER` / `XRK_ACP_AGENT`
* 新增 MCP HTTP 设备码登录：`xrkh mcp login`，令牌存 `~/.xrk/mcp-tokens/<server>.json`
* 新增技能安装 `xrkh skill add / list / remove / path`：本地目录或 git 仓（`#subdir` 从多技能仓里取一个），装前 fail-closed 校验

**SDK**

* 新增 Python SDK（`sdks/python`，仅标准库）：`HarnessClient`（HTTP）与 `StdioHarnessClient`（ACP）

## 完善 / Improved

* 工具渲染词汇表（`FileDiff` / `ToolCallView` / `ToolResultView` 等）收敛到 `@xrkseek/core-tools` 单一真源，`@xrkseek/xrk-tools/presentation` 改为转发；远端导入路径不变，不再维护第二套卡片定义
* 插件钩子 `hooks.onPre[]` / `hooks.onPost[]` 并入现有 ToolPipeline（policy 与 read-only 之后），不另起第二套瀑布
* 新增文件式扩展点：`~/.xrk/hooks.json` 与 `{workspace}/.xrk/hooks.json`（shell `PreToolUse`：exit 2 或 JSON `decision:block`）、`webhooks.json` 出站生命周期通知
* 插件可声明 `"required": true`，加载失败即中止 Host spawn；未声明则单插件失败只记入 `failures`，不拖垮其余
* 会话日志：`user/message.content` 支持 `ContentBlock[]`（text / image / file），新增 `workspace/changes`（`runTurn` 自动 append）与 `image/offload`（永久省略输入图出现位置）
* 读文档正文：支持 `.docx` / `.pdf` / `.ipynb` 文本层抽取；PDF 无可提取文本时明确返回提示而非空结果，扫描件不假装成功
* 侧栏策略拒绝统一走 `PolicyWireError` / `PolicyWireDetails` 载荷，不再各处手搭 `details` 形状

## 其他变更 / Other

* **破坏性**：`session.fork` 的血缘默认值由 `continuable` 改为 `fork`，且 `subagent.list` 只列工具委托的子代理——UI 分支不再出现在其中。需要旧行为请显式传 `linkMode: "continuable"`
* 修正预发布版本的发包语义：`scripts/release.mjs` 现按版本 prerelease 标识自动附 npm `--tag`（本版为 `rc`）并给 GitHub Release 加 `--prerelease`；此前发布 rc 会把它顶成 npm `@latest` 与仓库 Latest
* 全仓类型检查与 lint 归零：`tsc -b --force` 的 18 处报错（集中在 `exactOptionalPropertyTypes`、`BoundedTextBuffer` 与 `Buffer` 泛型方差、策略 `details` 载荷形状）与 `eslint` 的 9 处报错（`no-control-regex`、`no-unnecessary-type-assertion`、`preserve-caught-error`、`no-useless-assignment`）已全部修完
* 本版为 `MINOR=4` 预览线首号，不是正式线补丁

## 安装 / Install

```bash
npm install -g @xrkseek/harness-cli@0.4.0-rc.1
xrkh web
```

也可 `npx @xrkseek/harness-cli@0.4.0-rc.1 web`，或 `@rc`。预览线不覆盖 `@latest`：日常安装仍用 `npm install -g @xrkseek/harness-cli@latest`（v0.3.11）。

SDK：`pnpm add @xrkseek/harness@0.4.0-rc.1`

Python SDK（本仓）：`pip install -e sdks/python`
