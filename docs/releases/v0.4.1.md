# v0.4.1

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

**补丁号，只做两件事**：修掉一条**对话线格式（wire shape）缺陷**——易变上下文（时钟、session id）过去会被单独拼成一条 `user` 消息发给模型；以及把**中文界面这条链**接到底层（界面语言真正驱动推理与回复语言，若干客户端文案进词典）。公共 API 与配置面**没有破坏性变更**。

A patch release with two changes: a **wire-shape fix** — per-turn volatile context (clock, session id) used to be sent as its own `user` message — plus finishing the **Chinese UI chain** so the interface language actually drives reasoning and reply language.

---

## 一、问题：模型对着"会话标记"回话 / The bug

一次会话里，模型每收到一句人类的真实发言，后面就被追加一条**只含元数据**的 `user` 消息：

```
[user]      （人类的真实请求）
[assistant] tool_use
[user]      [volatile] time: … session: …      ← 病灶：一条"没人说话"的 user 消息
```

模型没有义务分辨"这是系统塞的元数据"还是"用户又开口了"。一条 `user` 消息只要**除元数据外没有可见内容**，它读起来就是**用户在说话**，于是模型停下来应答它——表现为"每轮先回一句会话标记、不干活"。工具循环里每一步都会追加一条，症状按步数放大。

The model has no reason to distinguish injected metadata from a human turn. A `user` message with no visible content _is_ "the human just spoke", so the model answers it instead of doing the work — and the tool loop re-emits one per step.

同类症状的另一面在界面：这类片段被投影成独立对话节点后，渲染器遇到不认识的节点类型直接抛错，面板留下 `Slot conversation.chat.node failed to render`。

## 二、修复：易变层折叠进当前 user 消息的尾缀 / The fix

**结构上不再存在"只含元数据的 turn"**，而不是用提示词命令模型"别理它"——后者是拿文字补丁盖结构洞，越堆越硬，衔接只会更差。

- `assembleThreeLayers`（`@xrkseek/core-system-prompt`）：`history` + **一条**当前 `user` 消息，人类文本在前、易变块折叠在其**尾缀**，且带 `[/volatile]` 闭合（旧实现只写开标签，模型无法判断块何时结束）。
- **同 turn 的后续 step（没有人类内容）：不追加任何消息**，请求就落在真实对话（`tool_result` / `assistant`）末尾——对话前缀因此逐字节稳定，provider 的 prompt cache 不被每步挪动。
- 冷启动（历史为空且无人类文本）仍兜底一条，保证线上不出现空 `messages`。
- 新增可复用判定：`hasHumanUserText`（零宽占位符 / 纯空白不算人类内容）、`stripVolatileBlock`、`isMetadataOnlyUserMessage`。
- `agent-loop` 出站处把 `isMetadataOnlyUserMessage` 作为**结构不变量**执行：这样的消息不进请求。
- `buildVolatileUser` / `mergeHistory` 保留但标 `@deprecated`（补丁号不动公共 API），新代码一律走 `buildVolatileBlock`。

```
[user]      （人类的真实请求）
[assistant] tool_use
[user]      人类文本 …
            [volatile] … [/volatile]     ← 折叠进同一条消息的尾缀
```

**测试锁住**：`three-layer.test.ts`（角色序列快照、后续 step 零追加、冷启动兜底、`[/volatile]` 闭合）、`fixtures.test.ts` + `fixtures/agt-golden.ts`（契约级角色序列）、`agent-loop/tests/assemble.test.ts`（携带易变块的那条剥掉块之后**仍有可见文本**）。

## 三、中文这条链接通了 / The Chinese chain

- **Host → 预设**：`createHostManager` 读 Settings 的 `locale.preference`，并兼容旧桌面把语言写在 `ui.locale` 的情况（否则一路掉进语言中立的兜底文案，推理漂回英文）；`locale` 命名空间变更并入 agent 失效名单。
- **预设 → 提示词**：`presets/harness` 注册 `language` 段（`order: 1`，紧跟 persona），`zh` / `en` / 未配置三分支——未配置时**跟随用户最近一条消息的语言**，不默认英文。
- **客户端词典**：`ui-plan`、`ui-conversation`、`session-log-export` 的硬编码文案移入各自 `locales.ts`；`ReasoningRow`、`PreviewTabs`、`HeaderAction`、`presentation.ts` 改为取词典。门禁的 `verify-client-ui-i18n` 校验通过。

## 四、文档 / Docs

`docs/llm-provider-registry.md`（中英对照的缓存表）、`packages/core/system-prompt/README.md` 同步到新线格式：易变层不进 `system`、折叠进当前 `user` 尾缀、无人类内容的 step 不追加消息。

## 五、升级 / Upgrade

```bash
npm i -g @xrkseek/harness-cli@0.4.1
xrkh web
```

无需迁移：会话日志格式、配置面、插件契约均未变。已装 0.4.0 的桌面直接升级即可；**旧 Host 需重启**才会用上新线格式（运行中的进程仍按旧格式发请求）。
