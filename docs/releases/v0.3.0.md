## 新增 / Added

### 进程半部即时软停用

* Settings 停用 / 启用后，Host 本进程调用 `reconcileManagedProcessPlugins`：停用 → `unregister`；启用 → 再 `discover` + `load`
* 跳过 `mcp:*`（MCP 仍走 Settings MCP 面，不进 soft-disable 卸装）
* 磁盘上已删除、inventory 已无的包：本进程也会卸掉，避免幽灵工具
* Client 半部仍须刷新页面；列表对「磁盘意图 ≠ 本进程 live 集」标 `needsRestart`

### 共享磁盘契约（`@xrkseek/server-loader`）

* 新增 `managed-state` + `atomic-write`：Face / HTTP / CLI / Host **同一叶模块**读写
  * `.xrk-plugins.json` — managed 包真源（name / version / kind / source / clientInject…）
  * `.xrk-plugins-disabled.json` — soft-disable id 列表
  * `web/boot.json` — client overlay（由 inventory 重算）
* **durable id** = inventory 包名；key 与 `entry.name` 漂移时 canonicalize，别名可匹配
* orphan 停用 id 在 reconcile 时剪掉；写盘原子替换；内容不变不重写
* 避免 Face↔HTTP 环依赖、各处各写一份 disabled / boot

### Face / Settings 面

* `pluginInventory/update`：按 inventory `source`（缺则 `name@latest`）重装；成功后清 soft-disable 并 reconcile boot + 进程半部
* `pluginInventory/list`：停用行仍从 inventory 列出（`enabled: false`），并带 `version` / `kind` / `source` / 可选 `needsRestart`
* `syncManagedProcessPlugins`：setEnabled / remove / update 后由 Host 注入回调跑同一 reconcile
* Settings 卡：版本徽标、托管 / 需重启标签、启用态、展开详情（kind / source）、更新 / 停用 / 删除 / 打开目录

### CLI

* `xrkh plugin reconcile`：以 inventory 清 `web/plugins` 孤儿、重写 `web/boot.json`（跳过 soft-disable；全空删 boot）
* `add` / `remove` 自动 reconcile；`list` 对停用项标 `disabled`
* CLI inventory 读盘改走 loader；boot 重写委托 Face `reconcileClientBootAt`（与 Host 同路径）

### Host → CLI mutate（跨平台）

* 新增可测的 `planCliInvocation` / `quoteWindowsCmdArg` / `listCliInvocationCandidates`
* **永不** `shell: true`；`node` + `bin.js` 直接 argv（`Program Files` / 空格 / 非 ASCII 安全）
* Windows 裸 `.cmd` → `ComSpec /d /s /c` + 正规转义
* 候选：`XRK_HARNESS_BIN` → 仓内 `apps/cli/dist/bin.js` → `xrkh` → `xrk-harness`（仅 ENOENT 才回退，插件失败不静默换 CLI）

## 完善 / Improved

### Host 接线

* `hostPublic.pluginsDir` **始终**绝对路径（`XRK_PLUGINS_DIR` 或 `{XRK_HOME}/plugins`）
* 目录存在即 spawn / Settings 变更时 reconcile——不依赖「启动瞬间 config 是否已写入 pluginsDir」
* overlay `web/boot.json` 合并进产品壳前，再按 soft-disable（含别名）过滤一层，防陈旧 boot 把已停用 client 装回来
* HTTP / DSH / sidebar public handler 与 Face 共用同一 `pluginsDir`

### 库存语义

* 产品壳 cordis stub：**不**因 `kind: cordis` 变成 Settings 可管项；仅 inventory / staged client 的社区包 `managed: true`
* soft-disable 只作用于 managed 行；builtin / 壳内插件不可 Settings 停用删除
* 打开目录优先 `…/web/plugins/<id>`，再回退进程树根
* DSH market `disabled` 与 `.xrk-plugins-disabled.json` 对齐

### 写盘与 boot

* `reconcileClientBootAt`：按 inventory 的 `client|both` 生成 entries；stable `rev`（内容指纹）；空则删 boot 文件
* disabled 文件与 boot 同目录原子写，减少半截 JSON

## 修复 / Fixed

* Host「未配置 pluginsDir 但目录已在 / 会话中途装上」时：Face 已写 soft-disable，进程半部却不 reconcile
* soft-disable 只做字符串精确匹配、inventory key ≠ `entry.name` 时停用失效（canonicalize + 别名）
* Windows 下 Host 调 `xrkh.cmd` / 含空格路径 mutate 失败，或失败后误试下一个 CLI
* 停用 client 后库存行消失无法再启用；打开目录找不到 `web/plugins/<id>`（相对 [v0.2.7](./v0.2.7.md) 收口并纳入正式契约）
* 陈旧 `web/boot.json` 在 Host 重启后仍加载已停用 client（overlay 二次过滤 + 内容稳定 reconcile）

## 行为一览 / Behavior

| 半部 | Settings 停用后 | 再启用 | 要不要刷新 |
|------|-----------------|--------|------------|
| **进程**（tools / prompt / commands…） | 本进程 unregister | discover + load | 建议刷新壳；工具面即时 |
| **client**（`web/plugins`） | 踢出 `web/boot.json` | 写回 boot | **要**硬刷新 / 重启 `web` |
| **mcp:\*** | 不走 soft-disable | — | 用 Settings → MCP |
| **壳内 cordis stub** | 不可管 | — | — |

磁盘布局：

```text
~/.xrk/plugins/
  .xrk-plugins.json              # managed 真源
  .xrk-plugins-disabled.json     # soft-disable（可选）
  web/boot.json                  # client overlay
  web/plugins/<id>/client.js
  <id>/                          # 进程插件
```

## 升级 / Upgrade

| 从哪来 | 怎么做 |
|--------|--------|
| **0.2.7（末预览）** | `npm i -g @xrkseek/harness-cli@0.3.0`（或 `@latest`）→ `xrkh restart` → Ctrl+Shift+R |
| **0.2.0–0.2.6** | 同上；勿停在曾暂存失败的 **0.2.6** |
| **0.1.31（旧正式）** | 同上；能力面见 [status](../status.md)（含已并入的 0.2 预览能力） |
| **0.0.11 / `@preview`** | 改装 `@latest`；勿依赖 `preview` tag |

**可感知变化**

* 停用**进程**插件：本 Host 内立即卸装（不必为卸工具整进程重启）
* 停用**client**插件：须刷新后侧栏 / boot 才空；库存仍能看见并再启用
* 壳自带 cordis stub：Settings 不再出现可删的「托管」假行
