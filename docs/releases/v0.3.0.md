# v0.3.0

> **读者 / Audience**：终端用户 · 维护者（发行说明） / End users · Maintainers (release notes)

相对 [v0.2.7](./v0.2.7.md)：把 **0.2 预览线**收成 **正式公开线**；插件软停用 / 库存 / Host reconcile / CLI mutate 落成可依赖契约；**预览基线结束**（末号 **0.2.7**）；撤下旧预览留档 **0.0.11** 与 npm `preview` tag。

Relative to [v0.2.7](./v0.2.7.md): graduate the **0.2 preview line** into the **formal public line**; soft-disable / inventory / Host reconcile / CLI mutate become dependable contracts; **preview baseline ends** (last **0.2.7**); withdraw legacy preview archive **0.0.11** and the npm `preview` tag.

---

## 新增 / Added

* **进程插件软停用即时生效**：Settings 停用 / 启用后，Host 本进程跑 `reconcileManagedProcessPlugins`——停用 unregister、启用再 discover+load；跳过 `mcp:*`；磁盘上已删除的包也会卸掉。Client 半部仍须刷新页面（列表标 `needsRestart`）
* **软停用磁盘契约下沉**到 `@xrkseek/server-loader` `managed-state`：Face / HTTP / CLI / Host 共用同一读盘写盘面（durable 包名、别名规范化、orphan 剪枝、原子写），避免 Face↔HTTP 环依赖与各处各写一份 disabled 文件
* **Settings「更新」**：`pluginInventory/update` 按 inventory `source`（或 `name@latest`）重装；成功后清 soft-disable 并 reconcile boot / 进程半部
* **CLI `plugin reconcile`**：以 `.xrk-plugins.json` 为真源清理 `web/plugins` 孤儿目录、重写 `web/boot.json`（跳过 soft-disable；全空则删 boot）

## 完善 / Improved

* **Host `pluginsDir`**：始终解析为绝对路径并暴露给 Face / mutate / overlay；只要 `{XRK_HOME}/plugins`（或 `XRK_PLUGINS_DIR`）目录存在就 discover / reconcile，不依赖「启动当下是否已写进 config」
* **boot / disabled 写盘**：内容不变不重写；`web/boot.json` 按 inventory 的 client/both 行重算；Host 合并 overlay 时再次按 soft-disable（含 inventory 别名）过滤，防止陈旧 boot 把已停用 client 又加载回来
* **Settings 插件库存**：停用行仍从 inventory 列出（`enabled: false`，带 `version` / `kind` / `source`）以便再启用；打开目录优先 `~/.xrk/plugins/web/plugins/<id>`；社区 cordis 仅在有 staged client / inventory 时标 `managed`（产品壳 stub 不可 Settings 停用删除）
* **Host 调 CLI mutate**：全程不用 `shell: true`；`node` + `bin.js` 直接 argv（兼容 `Program Files` / 空格 / 非 ASCII 路径）；Windows 裸 `.cmd` 经 `ComSpec /d /s /c` 正规转义；候选顺序 `XRK_HARNESS_BIN` → 仓内 `apps/cli/dist/bin.js` → `xrkh` → 旧名 `xrk-harness`（仅命令不存在时回退）
* **DSH market compat**：`disabled` 列表与 soft-disable 文件对齐；安装 / 删除走同一 mutate 路径
* **教科书**：同步 [plugin-loader](../plugin-loader.md) · [modules/server-host](../modules/server-host.md) · [status](../status.md) · [publishing](../publishing.md)

## 删除 / Removed

* **公开预览基线**：不再把 0.2.x 标成「当前预览线」；末预览号为 **0.2.7**（说明仍可查阅，npm 中间号按 publishing 弃用）
* **旧预览留档 0.0.11**：文档 `docs/releases/v0.0.11.md` 撤下；npm 包 deprecate；`preview` dist-tag 不再保留为推荐安装入口
* GitHub Release 公开页只保留 **v0.1.31** 与 **v0.3.0**（其余历史 Release 可下线；仓库内 `docs/releases/v*` 仍可查）

## 修复 / Fixed

* 修复 Host 在「未配置 `pluginsDir` 但 `~/.xrk/plugins` 已存在 / 会话中途装上」时：Face 已写 soft-disable，进程半部却不 reconcile 的门闸不一致
* 修复 soft-disable 仅按字符串精确匹配、inventory key 与 `entry.name` 漂移时停用不生效的问题（canonicalize + 别名解析）
* 修复 Windows 下 Host 调 `xrkh.cmd` / 含空格路径时 mutate 失败或静默落到错误 CLI 的问题
* 修复停用 client 后库存行消失、无法再启用；以及打开目录只找进程树根、找不到 `web/plugins/<id>` 的问题（相对预览末号的收口，见 [v0.2.7](./v0.2.7.md)）

## 其他变更 / Other

* 公开基线 **v0.3.0**（**正式**，npm **`@latest`**）；上一正式留档 **v0.1.31**；0.2.x 为已结束的预览线
* `npm-prune-withdrawn` 保留集：**当前正式号 + 0.1.31**；发版后会尝试去掉 `preview` dist-tag
* CLI / SDK（`@xrkseek/harness-cli` · `@xrkseek/harness`）版本对齐 **0.3.0**

## 升级注意 / Upgrade notes

| 从哪来 | 怎么做 |
|--------|--------|
| **0.2.x（含 0.2.7）** | `npm i -g @xrkseek/harness-cli@latest` → `xrkh restart` → 浏览器硬刷新（Ctrl+Shift+R） |
| **0.1.31** | 同上；能力面以 [status](../status.md) 为准（含 0.2 预览线已合并能力） |
| **曾装 `@preview` / 0.0.11** | 改装 `@latest` 或 `@0.3.0`；勿再依赖 `preview` tag |

**行为变化（可感知）**

* Settings 停用 **进程**插件：本 Host 进程内立即卸装，无需整进程重启（仍建议刷新壳）
* Settings 停用 **client** 插件：从 `web/boot.json` 去掉条目；须刷新页面后侧栏 / boot 才真正消失
* 产品壳自带 cordis stub：**不会**出现可 Settings 停用 / 删除的「托管」行（仅 CLI 安装 / staged 的社区包可管）

## 安装 / Install

```bash
npm install -g @xrkseek/harness-cli@0.3.0
xrkh web
```

或 / or：`npm i -g @xrkseek/harness-cli@latest`

离线 / Offline：GitHub Release 资产 `xrkseek-harness-cli-0.3.0.tgz` · `xrkseek-harness-0.3.0.tgz`。

嵌入式 SDK / Embed：`pnpm add @xrkseek/harness@0.3.0`

**建议 / Tip**：升级后硬刷新浏览器。已停用的 client 侧栏插件需刷新后才从 boot 消失；进程半部可即时卸装。

## 验证清单 / Verify

- [ ] `xrkh web` 后 Settings → Plugins：能列出已装包；停用进程插件后工具立即不可见；再启用后恢复
- [ ] 停用 client 插件 → 刷新页面 → 侧栏 / boot 不再加载；库存仍可见该行并可启用
- [ ] 「打开目录」落在 `…/plugins/web/plugins/<id>`（有 client 半部时）
- [ ] 「更新」能按 source 重装；失败时有明确错误而非挂死
