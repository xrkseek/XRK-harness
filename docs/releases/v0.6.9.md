# v0.6.9

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.8](./v0.6.8.md)：**干员从「能装」走到「能长、能改、能还回去」**。铸造口收敛到 `team_save`（`kind=advanced` + `skills=` / `files=` / `env_prep=`），`team_import` 收窄成纯安装口（只接 `card=` / `pack=`）；新增 `team_export`（薄=JSON · 高级=zip，预置不可导出）、`team_remove`（按 scope 卸载）、`team_self`（干员在自己子会话里改自己的面）。高级包有了**公文包 (briefcase)**：派生时 **cwd 保持父工作区**，包根作为绝对路径注入 spawn preamble 与 `<session_capability>`，孩子在那儿读料、改料或拷进工作区——不再是「把工作区搬到包里」。包布局有白名单与一行契约，`team_save id=` 可只改一面、也可往公文包里**增量加料**。既有的 team UI RPC（炼包 / 派生 / 导出 / 拖包安装）本期接上公文包与导出闸，七个 team 工具也全部走调用卡片，面板与工具同面。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.9`（发包后）。

Relative to [v0.6.8](./v0.6.8.md): 干员 (Agent Team members) go from **installable** to **growable, editable and exportable**. Minting collapses into `team_save` (`kind=advanced` + `skills=` / `files=` / `env_prep=`) while `team_import` narrows to a pure installer (`card=` / `pack=` only). New: `team_export` (thin = JSON · advanced = zip; built-ins refused), `team_remove` (uninstall per scope) and `team_self` (a child revises its own surfaces). Advanced packs get a **公文包 (briefcase)**: spawning **keeps the parent workspace cwd**, the pack root is injected as an absolute path into the spawn preamble and `<session_capability>`, and the child reads/edits or copies from there — the workspace is no longer moved into the pack. Layout carries a one-line contract plus whitelist validation; `team_save id=` can patch a single surface **or merge new material into the briefcase**. The existing team UI RPCs (distill / dispatch / export / drag-install) are now wired to the briefcase and the export gate, and all seven team tools render call cards, so panel and tools share one surface. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.9` (after publish).

### 新增

* **`team_save kind=advanced` 铸造高级干员**：`env_prep` 写进 `env/SETUP.md`、`skills=[目录]` 收整棵技能树（含 `references/` 与资产）进 `skills/<id>/`、`files=[路径]` 收项目文件进包内 `workspace/`。设了这三者之一即自动按 advanced 处理；advanced 缺省 `scope=global`（薄卡缺省 workspace），回执直接带回 `briefcase`、实时 `inventory`（`materialsPath` / `materialsTop` / 每条技能路径）、`layout` 契约、`pathHint` / `shareHint` 与下一步（`next`）。
* **`team_self`：干员自己改自己的面**——`playbook` / `brief` / `inject` / `tools`（可选 `name`）。只有以 `member_id` 派生的子会话才注册这个工具（能力板标 `selfRevise`），按字段判存在、缺省字段保持原值；advanced 成员改 playbook 会同步写回包内 `playbook.md` 并重贴可迁移路径段。
* **`team_export`**：`id=` + 可选 `dir=`（缺省落会话 cwd）。薄卡出 `xrk-agent-member` JSON，高级包出 zip（文件名由 `safeStem` 清洗）。**预置 catalog（`mem_seed_*`）不可导出**：`catalogMemberExportProblem` 直接拒并提示「先以其为基底新建定制副本」。
* **`team_remove`**：按 `id=` + `scope=` 卸载（预置 id 同样拒删）。
* **公文包 (briefcase)：包 ≠ 工作区**：`resolveMemberPackHome` / `resolveMemberPackMaterialsDir` / `listMemberPackInventory` 解析并盘点包根。派生 advanced 成员时 **cwd 仍是父工作区**，preamble 与 `<session_capability>` 注入 `公文包 (briefcase)` · `pack_home` · `materials` · 每条 `skills/<id>/`（含 `references/`），并写明「不是 workspace cwd——在这儿读/改，或拷进工作区」。`worktree: true` 与公文包互不相干。
* **可迁移路径段**：`ADVANCED_PACK_PATHS_SECTION`（`## Paths (portable)`）幂等并入 advanced playbook——铸造时与后续修订时都会校验，写明「cwd = 父编码工作区 · 公文包另在别处 · 分享 zip 只用相对路径」。炼出来的干员不会把本机绝对路径烙进可分发包。`captureSessionPlaybook`（从会话记录取默认 name/playbook）改由 UI 侧 `team/capture` 调用。
* **包布局成文 + 白名单**：`AGENT_MEMBER_PACK_LAYOUT` 一行契约——必需 `.xrk-agent-pack` · `manifest.json`（kind `xrk-agent-pack`）· `playbook.md`，可选 `skills/<id>/`（+`SKILL.md`、`references/`）· `workspace/` · `env/SETUP.md`。`validatePackLayout` 拒绝未知根名、路径穿越、缺 `SKILL.md` 的技能目录。
* **UI RPC 接上公文包**：`team/capture` · `team/dispatch` · `team/export` · `team/importPack` 这组 RPC 自 v0.6.8 就在（与 list/upsert/remove 并列），本期把面板侧的派生与导出接到新模型上——`teamDispatch` 解析 `resolveMemberPackHome` / `resolveMemberPackMaterialsDir` / `listMemberPackInventory` 并把 `packHome` / `packMaterials` / `packInventoryLines` 交给 spawn，`teamExport` 走 `catalogMemberExportProblem` 拒导预置。

### 完善

* **`team_import` 收敛为纯安装口**：只接 `card=` / `pack=`。传 `from_session=true` 现在被明确拒绝并指路 `team_save kind=advanced`——铸造与安装分成两条不相撞的路。
* **`team_save id=` 局部修订 + 增量加料**：`patchExistingMember` 允许只改 playbook / inject / tools / name 而保留其余字段与 `kind`；advanced 成员还能把新的 `skills=` / `files=` / `env_prep=` **并入已有公文包**（`mergeIntoMemberPack`），不必重交整包。包已从磁盘丢失时报错并提示「`team_import pack=` 或 `team_save kind=advanced` 重来」，而不是静默造半个包。预置 id 仍拒。
* **子代理工具面按成员收紧**：`applyRosterToolPolicy` 这个函数 v0.6.8 就有，但派生路径一直没调它——本期 `runtime.ts` 正式接上 `applyRosterToolPolicy(agent.tools, childLink.role, childLink.tools)`，成员自带的 `tools` allow/deny 才真正生效；role 地板同时从 3 个（`team_save` / `team_import` / `team_ready`）扩到 5 个（再加 `team_export` / `team_remove`）；带 `member_id` 的孩子额外拿回 `team_self`。文案改成「team_list + team_self：改**你自己的** playbook/inject/tools，不许铸包/导出/删别人」。
* **七个 team 工具统一走调用卡片**：`presentCall`（`teamPresent`）——执行类 `kind=execute`、查询类 `kind=search`，Team 面板与工具调用同步可见。
* **`subagent member_id` 文案更准**：明确「member 的 tools + inject + playbook ≠ 父面」、子会话可 `team_self` 修订自己、找不到成员时的下一步指向 `team_save`（炼）/ `team_import pack=`（装朋友包）。
* **`missingMemberHint` 更可操作**：区分「根本不存在」与「在别的画布 workspace-scoped」，后者给出去哪迁的提示；`team/dispatch` 同样按 `findHome` 判 scope 后报该去哪条画布。
* **干员生命周期成文**：`xrk-delegate` 重写为 mint / install / revise / uninstall / share 五态表——薄 → `team_save`；高级 → `team_save kind=advanced` → `team_ready` → `team_export` 出 zip；父改面 `team_save id=`、子改面 `team_self`；导出 ≠ 预置 catalog；并写明主会话写 advanced playbook 时要交代公文包里有什么。路径口径统一成**相对路径**。
* **配置面 parity 明确**：`settings_*` = Settings UI、`team_*` = Team UI（同一批干员，人和 AI 都能建）、写 skill 习惯仍走 `xrk-create-skill` 而非干员包。向阳能力板副标题补上 `settings+team_*`。`session-identity-scenarios` 与向阳 `xrk-demand-translate` / `xrk-home-config` / `xrk-skill-merge` 文案同步，向阳技能种子 **revision 4**。

### 修复

* **预置成员不再出现导出按钮**：`canExport` 排除草稿与 `catalogSeed`，中英文案同步为「预置只读、**不可导出**」（原来只写只读，点了才知道不行）。
* **`productHome` 契约随新路径扩展**：v0.6.8 已把两处可选参数收紧成 `?: string | undefined`；本期新增的技能/文件收集与打包路径（`collectPackSkillFiles` · `collectPackWorkspaceFiles` · `buildAgentMemberPackZip` · `resolveMemberPackHome` / `resolveMemberPackMaterialsDir` / `listMemberPackInventory` / `mergeIntoMemberPack`）同样标注并透传 `input.productHome`，调用点不再撞 TS2379。

## 验证

* **炼与发**：某会话里 `team_save kind=advanced` +（可选 `skills=` / `files=` / `env_prep=`）→ `team_list` 见 `advanced` 未就绪带 envPrep → 按 `env/SETUP.md` 准备 → `team_ready` → `team_export` 得 zip → 换机 `team_import pack=` → 派生后 cwd 仍是父工作区，能力板/preamble 有 `公文包 (briefcase)` · `pack_home` · `materials` · 每条 skill 路径。
* **增量加料**：对已就绪的 advanced 成员 `team_save id=… files=[新文件]` → 回执 `inventory` 里出现新材料，原 skills/env 未被清空。
* **子会话自改**：`subagent member_id=…`，在其会话里 `team_self playbook=…`；回父 `team_list` 看到新面，包内 `playbook.md` 同步，且路径段不重复追加；同一子会话调 `team_save` / `team_export` / `team_remove` 均不在工具面上。
* **导出闸**：对 `mem_seed_*` / `mem_hwgen` 调 `team_export` 被拒并提示先定制；UI 上预置行无导出按钮，文案读作「只读、不可导出」。
* **卸载**：`team_remove id=… scope=workspace|global`；预置 id 拒绝。
* **包面校验**：把一个不存在的 id 交给 `subagent member_id=`，回执区分「不存在」与「在别的画布」并给下一步。
* **回归**：`pnpm check` 全绿（TS strict / eslint / i18n / 测例）。

### Added

* **Mint advanced members with `team_save kind=advanced`**: `env_prep` writes `env/SETUP.md`, `skills=[dirs]` collects whole skill trees (including `references/` and assets) into `skills/<id>/`, `files=[paths]` collects project files into the pack's `workspace/`. Setting any of the three implies advanced; advanced defaults to `scope=global` (thin defaults to workspace). The receipt carries `briefcase`, a live `inventory` (`materialsPath` / `materialsTop` / per-skill paths), the `layout` contract, `pathHint` / `shareHint` and the next step (`next`).
* **`team_self` — a member edits itself**: `playbook` / `brief` / `inject` / `tools` (optional `name`). Registered only for children spawned with a `member_id` (the capability board marks `selfRevise`), patches by presence so omitted fields keep their values, and for advanced members the playbook syncs back into the pack's `playbook.md` with the portable path section re-applied.
* **`team_export`**: `id=` plus optional `dir=` (defaults to the session cwd). Thin cards become `xrk-agent-member` JSON, advanced packs become a zip (sanitized via `safeStem`). **Catalog built-ins cannot be exported**: `catalogMemberExportProblem` refuses and tells you to mint a custom copy from that template first.
* **`team_remove`**: uninstall by `id=` + `scope=` (catalog ids refused).
* **公文包 (briefcase): pack ≠ workspace**: `resolveMemberPackHome` / `resolveMemberPackMaterialsDir` / `listMemberPackInventory` resolve and inventory the pack root. Spawning an advanced member **keeps the parent workspace cwd**; the preamble and `<session_capability>` inject `公文包 (briefcase)` · `pack_home` · `materials` · every `skills/<id>/` (with `references/`), stating it is *not* the workspace cwd — read/edit there or copy into the workspace. `worktree: true` stays unrelated to the briefcase.
* **Portable paths section**: `ADVANCED_PACK_PATHS_SECTION` (`## Paths (portable)`) merges idempotently into advanced playbooks — checked both when minting and when later revising — spelling out "cwd = parent coding workspace · briefcase lives elsewhere · relative paths only when sharing the zip". A distilled 干员 never bakes host-absolute paths into a shareable pack. `captureSessionPlaybook` (default name/playbook from the transcript) is now called by the UI-side `team/capture`.
* **Layout as a contract, enforced**: `AGENT_MEMBER_PACK_LAYOUT` states it in one line — required `.xrk-agent-pack` · `manifest.json` (kind `xrk-agent-pack`) · `playbook.md`; optional `skills/<id>/` (+`SKILL.md`, `references/`) · `workspace/` · `env/SETUP.md`. `validatePackLayout` rejects unknown root names, path traversal and skill dirs without a `SKILL.md`.
* **The team UI RPCs learn the briefcase**: `team/capture` · `team/dispatch` · `team/export` · `team/importPack` already shipped in v0.6.8 alongside list/upsert/remove; this round the panel-side dispatch and export are rewired to the new model — `teamDispatch` resolves `resolveMemberPackHome` / `resolveMemberPackMaterialsDir` / `listMemberPackInventory` and hands `packHome` / `packMaterials` / `packInventoryLines` to the spawn, while `teamExport` runs `catalogMemberExportProblem` so built-ins cannot be exported.

### Improved

* **`team_import` narrowed to a pure installer**: accepts `card=` / `pack=` only. Passing `from_session=true` is now refused with a pointer to `team_save kind=advanced` — minting and installing no longer collide on one entry point.
* **Partial edits and incremental top-ups via `team_save id=`**: `patchExistingMember` changes playbook / inject / tools / name while keeping everything else and the `kind`; an advanced member can also **merge** new `skills=` / `files=` / `env_prep=` into the existing briefcase (`mergeIntoMemberPack`) instead of re-submitting the whole pack. If the pack is gone from disk the error tells you to `team_import pack=` or re-mint rather than silently building half a pack. Catalog ids stay refused.
+'s own `tools` allow/deny; a child spawned with `member_id` regains `team_self`. Copy now reads "team_list + team_self: revise YOUR playbook/inject/tools — no mint/export/remove of others."
* **All seven team tools render call cards**: `presentCall` (`teamPresent`) — executions as `kind=execute`, queries as `kind=search` — so the Team panel mirrors every tool call.
* **More precise `subagent member_id` copy**: states that a member's tools + inject + playbook differ from the parent, that a child may `team_self`, and points a missing member at `team_save` (mint) / `team_import pack=` (install a friend's pack).
* **Actionable `missingMemberHint`**: distinguishes "does not exist" from "workspace-scoped on another canvas", naming where to move it; `team/dispatch` resolves via `findHome` and reports the same.
* **Member lifecycle documented**: `xrk-delegate` rewritten around mint / install / revise / uninstall / share — thin via `team_save`, advanced via `team_save kind=advanced` → `team_ready` → `team_export` (zip), parent edits with `team_save id=`, child edits with `team_self`, exporting is not for catalog built-ins — and it now asks the main session to describe what the briefcase contains. Path wording standardizes on **relative paths**.
* **Config-surface parity**: `settings_*` = Settings UI, `team_*` = Team UI (same members, built by human or AI), and authoring skill habits stays with `xrk-create-skill` rather than a 干员 pack. The Xiangyang capability subtitle now reads `settings+team_*`. `session-identity-scenarios` plus the Xiangyang `xrk-demand-translate` / `xrk-home-config` / `xrk-skill-merge` bodies are synced; Xiangyang skill seeds **revision 4**.

### Fixed

* **Built-ins no longer show an export button**: `canExport` excludes drafts and `catalogSeed`, and both locales now read "read-only **and not exportable**" instead of advertising an action that fails.
* **The `productHome` contract extends to the new paths**: v0.6.8 already narrowed two optional parameters to `?: string | undefined`; this round the new collection and packing paths (`collectPackSkillFiles` · `collectPackWorkspaceFiles` · `buildAgentMemberPackZip` · `resolveMemberPackHome` / `resolveMemberPackMaterialsDir` / `listMemberPackInventory` / `mergeIntoMemberPack`) carry the same annotation and pass `input.productHome` through, so no call site trips TS2379.

## Verify

* **Distill and share**: `team_save kind=advanced` (+ optional `skills=` / `files=` / `env_prep=`) → `team_list` shows advanced and not-ready with envPrep → prep per `env/SETUP.md` → `team_ready` → `team_export` yields a zip → on another machine `team_import pack=` → the spawned child keeps the parent workspace cwd while preamble/capability show `公文包 (briefcase)` · `pack_home` · `materials` · every skill path.
* **Top-up**: `team_save id=… files=[new file]` on a ready advanced member → the receipt `inventory` shows the new material and existing skills/env survive.
* **Child self-edit**: `subagent member_id=…`, then `team_self playbook=…` inside that session; the parent's `team_list` shows the new surface, the pack's `playbook.md` is synced, the portable path section is not appended twice, and `team_save` / `team_export` / `team_remove` are absent from that child's surface.
* **Export gate**: `team_export` on `mem_seed_*` / `mem_hwgen` is refused with a pointer to mint a copy; built-in rows show no export button and read "read-only and not exportable".
* **Uninstall**: `team_remove id=… scope=workspace|global`; catalog ids refused.
* **Member surface**: pass a nonexistent id to `subagent member_id=` — the receipt distinguishes not-found from lives-on-another-canvas and names the next step.
* **Regression**: `pnpm check` green (TS strict / eslint / i18n / suites).
