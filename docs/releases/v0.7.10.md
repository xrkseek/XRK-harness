# v0.7.10

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

## 中文

相对 [v0.7.9](./v0.7.9.md)：四区策展记忆终于真正注入 system prompt 并按 `### GLOBAL / WORKSPACE / SESSION / AGENT curated memory` 标注； процесс折叠头布局与 live 判定回归修复；USER.md 可写、记忆上限可配；TTS 不再注入引导文案。

### 四区策展记忆（主线）

* **四区记忆现在真的注入**：`curatedMemory` 之前只在 `=== false` 时向下传，正常 provider 被丢弃，harness composition 回落到 home-only 单区。现在原样透传给 `createHarnessComposition`。
* **四区注入改用 store 的 `isLayered`**：`presets/harness` 与 `layered` 统一判定，不再重复推导。
* **AGent 区称呼跟随设置**：新增可选 `agentLabel`，zone 头、工具描述、zoned policy 文案不再写死「干员」，由 Settings `ui-presence` 的层级叫法决定；Host 从 Face 读 `readSeatTitles(...).agent`（含自定义 `titleAgent`）传入。
* **新增 `scopedCuratedMemoryPromptText()`**：按 scope 生成策展记忆提示文本。
* **USER.md 可写**：`memory` 工具 `target` 支持 `memory | user`，描述与 `CURATED_MEMORY_PROMPT_TEXT` 更新（USER.md 只收用户自述事实）。
* **记忆上限可配**：新增 `CuratedMemoryLimits`、`CURATED_MEMORY_LIMIT_MIN/MAX`（200/20000）、`resolveCuratedMemoryLimits()`；`createCuratedMemoryStore({ limits })`；所有 usage/render 路径按配置 cap 计算，不再硬编码 2200/1375。Settings `curated-memory` ns 新增 `memoryLimit` / `userLimit`（step 100，min 200，max 20000，默认 2200/1375）；插件卡加两个数字字段（三语文案）。
* **policy 文案说明 cap 来自设置**。

### 过程折叠头布局（client）

* **过程头活动行贴着工具名左对齐**：修复 0.7.9 的 CSS 顺序 bug——`.processGroupSummaryLiveInline { flex: 0 1 auto }` 被后面同 specificity 的 `.processGroupSummaryLive { flex: 1 1 auto }` 覆盖，导致折叠头「过程 · bash」与右侧累计活动行之间撑出一大段空白。改成 `:global([data-process-group]) .processGroupSummaryLiveInline`（0,2,0），不再依赖声明顺序。
* **immediate / 精简模式恢复实时工具名**：修复 0.7.9 的 live 门控回归——`live = !settled && (...)` 让 `foldWhen: immediate` 恒 settled → 折叠时实时工具名消失。改成 `running || (!settled && reasoning-only)`。

### TTS 引导注入移除

* **TTS 开着不再注入 `<tts_available>` 引导文案**：删除 `packages/server/face/src/tts-availability.ts` 及其导出/注册；工具本身仍由 `tts.enabled` 绑定。避免无谓的 prompt 膨胀。

### 底层质量

* **`layered`**：`isLayered` 单一判定；`preset` 不再重复推导；`limits` 透传到四区每个 store。
* **`presets/server`**：`curatedMemory` 原样透传，不再仅在 `=== false` 时下传。

### 文档

* `docs/curated-memory.md`：USER.md 可写、cap 可配、target 说明（中英两段）。
* `docs/status.md`：记忆行补 cap 可配 / USER.md 可写 / agentLabel。

# Release Notes

> **Audience**: End users · Maintainers

## English

Relative to [v0.7.9](./v0.7.9.md): the four-zone curated memory is now actually injected into the system prompt and labeled `### GLOBAL / WORKSPACE / SESSION / AGENT curated memory`; process-header layout and live-gating regressions from 0.7.9 are fixed; USER.md is writable and memory caps are configurable; TTS no longer injects guidance text.

### Four-zone curated memory (mainline)

* **Four-zone memory is now actually injected**: `curatedMemory` previously only forwarded when `=== false`, dropping the normal provider so the harness composition fell back to the home-only single zone. It is now forwarded verbatim to `createHarnessComposition`.
* **Four-zone injection now uses the store's `isLayered`**: `presets/harness` and `layered` share one predicate, no re-derivation.
* **Agent-zone label follows settings**: new optional `agentLabel`; zone header, tool description, and zoned policy text no longer hardcode "干员" — driven by Settings `ui-presence` hierarchy labels. Host reads `readSeatTitles(...).agent` (including custom `titleAgent`) from Face and passes it through.
* **New `scopedCuratedMemoryPromptText()`**: generates curated-memory prompt text per scope.
* **USER.md writable**: `memory` tool `target` now supports `memory | user`; description and `CURATED_MEMORY_PROMPT_TEXT` updated (USER.md only collects user-stated facts).
* **Configurable memory caps**: new `CuratedMemoryLimits`, `CURATED_MEMORY_LIMIT_MIN/MAX` (200/20000), `resolveCuratedMemoryLimits()`; `createCuratedMemoryStore({ limits })`; all usage/render paths compute against the configured cap instead of hardcoded 2200/1375. Settings `curated-memory` ns adds `memoryLimit` / `userLimit` (step 100, min 200, max 20000, default 2200/1375); the plugin card adds two numeric fields (trilingual).
* **Policy text notes caps come from settings**.

### Process header layout (client)

* **Process-header activity row sits flush left next to the tool name**: fixes the 0.7.9 CSS ordering bug where `.processGroupSummaryLiveInline { flex: 0 1 auto }` was overridden by the later same-specificity `.processGroupSummaryLive { flex: 1 1 auto }`, leaving a large gap between "process · bash" and the right-hand activity line. Now `:global([data-process-group]) .processGroupSummaryLiveInline` (0,2,0), order-independent.
* **Immediate / compact mode restores live tool names**: fixes the 0.7.9 live-gating regression where `live = !settled && (...)` made `foldWhen: immediate` always settled, dropping the live tool name while folded. Now `running || (!settled && reasoning-only)`.

### TTS guidance injection removed

* **TTS no longer injects `<tts_available>` guidance text**: deleted `packages/server/face/src/tts-availability.ts` and its exports/registration; the tool itself is still bound by `tts.enabled`. Avoids needless prompt bloat.

### Underlying quality

* **`layered`**: single `isLayered` predicate; `preset` no longer re-derived; `limits` forwarded to every zone store.
* **`presets/server`**: `curatedMemory` forwarded verbatim, no longer only when `=== false`.

### Docs

* `docs/curated-memory.md`: USER.md writable, caps configurable, target notes (both languages).
* `docs/status.md`: memory row adds configurable caps / USER.md writable / agentLabel.
