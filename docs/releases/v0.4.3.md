# v0.4.3

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）
> **补丁号，动多条缝**：会话取消链路硬化（乐观 `running:false` · 有界 join · 级联子代理）· Host 共享 shell 沙箱 · spill token 计量 · compaction 默认对齐 · DSH 兼容层诚实化 · 客户端 job 状态前向兼容硬化。
> A patch release touching several seams at once: the session-cancel chain (optimistic `running:false`, bounded join, cascade to subagents), Host-wide shared-shell sandboxing, spill token metering, compaction default alignment, DSH-compat honesty, and forward-compatible client job-status rendering.

## 一、会话取消链路硬化 / Session-cancel chain

| 症状（模型/用户看到的）                                    | 机制（真实原因）                                                                 | 修法                                                                                                              |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 会话里工具卡死（挂起的 git/fs/工作区快照），`cancel` 也回不来 | drain body 无视信号，`cancel` 无限 join 清理                                      | `cancel` 支持 `cause` / `timeoutMs` / `onAbort`：信号 cause 透传、**有界 join**（超预算照样 resolve）、abort 同步回调 |
| cancel 期间又 admit 了一条消息，它永远躺在队列里             | `wake` 在 stopping 中被吞掉，follow-up drain 被 veto                            | `stopping` 不再否决 follow-up：cancel 后落地的 wake 是**新 admit**，仍欠一次 drain                                |
| UI 一直显示 running，直到卡住的工具最终返回                 | `running:false` 只在 drain 结束后才发                                             | **乐观发布** `running:false`（卡住也立即变 idle），drain 结束后再补发终态                                        |
| 取消父会话，子代理还继续跑，成了孤儿子会话                   | cancel 只停自己，delegated 子树没人管                                             | **级联 cancel 委托子代理**（fire-and-forget 子树，深度受 subagent registry 限制）                                |
| 父被 abort 时 `waitDrainIdle` 永久挂住                        | 无竞速，等一个已死的链                                                   | `abortable()` 竞速：信号到达即脱离等待，不钉死调用方                                                            |

## 二、Host 共享 shell 沙箱 / Shared-shell sandboxing

- 新增 `createHostShellPrepareArgv`：Host 级共享 shell 的 `prepareArgv` **惰性解析**沙箱栈——Face settings（迟于 shell 创建到达）与 per-session `sandboxMode` 都被兑现：`danger-full-access` 解锁、其余全部 confine。
- `exec-shell` 的 `prepareArgv` 增第四参 `ctx.ownerSessionId`：会话归属参与 confine 判定。
- 修复 harness preset `sharedShell ?? createLocalShell` 分支：注入的 shared shell 原本会**完全绕过沙箱**跑 bash——现在走生产 confine 路径。回归测试 `host-shell-sandbox.test.ts` 锁住三种模式（workspace-write / danger-full-access / 无 ownerSessionId 兜底）。

## 三、Spill token 计量 / Token metering

- 新增 `toolResultMaxInlineTokens`（DSH `maxInlineTokens` 语义），设置时**优先于**字节上限。
- `DEFAULT_SPILL_INLINE_TOKENS = 16_000`、`estimateSpillTokens`（chars/4，与 `surface-estimate.ts` 同规则，`@xrkseek/spill` 保持 leaf）。
- 多字节语言（CJK ~3+ bytes/token）此前会被字节预算**提前截断**；token 计量使上限**语言中立**。省略提示改报 `~N tokens`。

## 四、Compaction 默认对齐 / Default alignment

- `DEFAULT_COMPACTION_KEEP_TOKENS` 8k → **24k**、buffer 2k → **4k**，与 Face `settings-schemas.ts` 产品默认（`keepTokens: 24_000` / `bufferTokens: 4_000`）**对齐**——两处独立「默认数」失步会让 Settings UI 显示的数值与实际运行行为脱节。

## 五、DSH 兼容层诚实化 / DSH-compat honesty

- 扫描社区 `client.js` 的 `slots.register`（`sidebar.panellist` / `main` / `main.conversation` 全局面板形状）：`auditCommunityClientSurface` 分类 `shell-seat` / `missing-seat`，**诚实暴露缺口**而非在 `SlotCore`「not declared」里静默死掉。
- `DSH_COMPAT_KNOWN_GAPS` 诚实枚举：`web-panel-global-registry`（missing-seat）、`cordis-dual-half-inspect` / `third-party-di`（honest-stub，第三方 Host 内核嵌入边界外）。
- 新增编译期边界测试 `dsh-compat-boundary.test.ts`：dsh-compat 内部不反向依赖主业务包，主项目不直接 import dsh-compat 子路径。

## 六、客户端前向兼容硬化 / Client forward-compat

- `ui-jobs` / `ui-workflow-run`：job / workflow 状态点从 switch 改为**映射表**——较新 host 新增的未知 wire status 渲染**琥珀点**而非抛错，单行不会崩掉整个列表。
- `ContextBody`：context-fragment 身份行（`fragmentId` / `fragmentKind` + caption），管道可重算、读者需要的是提供者与 id。
- `ConversationController`：新增 `resolveImage`（会话授权的历史图片 URL 解析与缓存）；图片媒体类型走 `SUPPORTED_IMAGE_MEDIA_TYPES` 集合。
- 类型打磨：`JobId` 品牌化（`xrk-host-apiproxy`）、`AttachmentId` 品牌、`CommandClaim` 再导出等。

## 七、兼容性与边界 / Compatibility

- **破坏性变更（内部契约）**：`SessionDrainLatch.cancel` 现接受可选 `options` 参数（源码兼容，二进制不兼容）；`SessionDrainHub.cancel` / `wireDrainStatus.cancel` 同步扩参。
- 新增 Face 契约：`session.cancel` 乐观 `running:false` + 级联子代理（`cascade`）。
- `exec-shell` `prepareArgv` 签名增第四参（`ctx`）——第三方传 `prepareArgv` 的实现需补参，否则第三个参数之后的行为不变。
- 客户端：job 状态点表化是渲染层行为，不涉及 wire 格式变更。

## 八、测试锁住 / Tests

- `latch.test.ts`：cancel 选项（cause 透传 / 有界 join / onAbort）、post-cancel wake 不再滞留。
- `harness-path.test.ts`：`session.cancel` 级联到 delegated 子会话并 idle 它们。
- `host-shell-sandbox.test.ts`：`createHostShellPrepareArgv` 三模式（workspace-write / danger-full-access / 无 ownerSessionId）。
- `job-list-shared.test.ts`：job 状态点表全部已知状态 + 未知状态降级琥珀。
- `dsh-compat-boundary.test.ts`：编译期边界（无反向依赖）。
- `dsh-community-audit.test.ts`：seat 分类（`shell-seat` / `missing-seat`）。
- `spill.test.ts`：token 计量（CJK 不提前截断）。

## 九、升级 / Upgrade

```bash
npm i -g @xrkseek/harness-cli@0.4.3
xrkh web
```

无需迁移：配置面、插件契约、会话日志格式均未变。**旧 Host 需重启**才会加载新行为——运行中的进程仍持有旧实现（表现为 cancel 可被卡死工具钉住、共享 shell 无沙箱）。
