# v0.6.5

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.4](./v0.6.4.md)：策略规则多了一层只读的布尔过滤，可以按参数内容决定拦不拦，而不是只看工具名；读文件在打开的那一刻才认符号链接，路径围栏不再靠先查后开；子进程拿不到父进程的环境变量凭据；`apply_edit` 的行尾差异不再直接失败；外呼请求带上一致的链路标识，报错回一行可追的 request-id；Shell Hook 补到 14 类事件；技能目录装不下时按相关性打包而不是从中间切断。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.5`。

Relative to [v0.6.4](./v0.6.4.md): policy rules gain a read-only boolean filter, so a rule can decide by argument content instead of tool name alone; a file read trusts the symlink at open time rather than by check-then-open; child processes no longer inherit credential-shaped environment; line-ending drift no longer fails `apply_edit` outright; outbound LLM calls carry one consistent trace id and errors return a followable request-id; Shell Hooks reach 14 event names; an over-budget skill catalog packs by relevance instead of cutting mid-entry. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.5`.

### 安全

* **策略规则可以按参数内容过滤**：规则新增可选的 `match.when`，是一段受限布尔表达式（如 `name == "bash" && args.command.includes("rm -rf")`）。加载时编译一次，表达式为假则本条规则不匹配、继续往下找。**没有引入第二套策略引擎**——ruleset JSON 仍是唯一入口，`when` 只是既有规则上的一个过滤器。表达式里不能用 `eval` / `vm` / `Function`，未知标识符、赋值、原型链访问在编译期就被拒；长度上限 512 字符、嵌套深度上限 32；字符串方法只开放 `includes` / `startsWith` / `endsWith` / `match`，正则只开放 `.test`。可引用的主体字段按 kind 给定（`tool.call` 给 `name` 与 `args`，`host.open` 给 `path`，`sidebar.embed` 给 `url` / `scheme`，`sidebar.fs` 给 `op` / `path`，依此类推），主体对象逐层冻结。运行时的类型错误（如对 `undefined` 调方法）判为不匹配，不会把异常抛到决策外。另外 `deny` / `ask` 现在可以省略 `names`：`when` 命中即对整个 kind 生效；`allow-only` 仍必须带 `names`。
* **读文件在打开那一刻才认符号链接**：`read_file` 一类读取改用 `O_NOFOLLOW` 打开（平台支持时），随后对已打开的文件描述符 `fstat` 复核。以前是先 `lstat`/`realpath` 判断再打开，两者之间换掉链接就能绕过路径围栏；这个窗口现在关掉了。围栏的根集合按当前权限档给出（工作区根、Host 可读根、额外可写根、会话根），`path=open` 时为空，即不施加链接约束。新增导出 `openNoFollowRead` / `readFileNoFollow`。
* **子进程拿不到父进程的凭据**：所有仓内派生进程共用一份环境清洗（`@xrkseek/exec-subprocess` 的 `childEnv` / `scrubbedParentEnv`，PTY 路径改为复用同一实现，不再是两份各写各的）。名字里含 `KEY` / `PASSWORD` / `SECRET` / `TOKEN` 的一律剥掉，`XRK_*` 与 `DSH_*` 前缀的 harness 身份变量也剥掉，`LD_*` / `DYLD_*` 这类动态链接器注入一并剥掉；`PATH`、`HOME`、locale、代理变量保留。调用方显式传入的条目在清洗之后合并，所以真要传就传得进去；Windows 上按大小写不敏感合并，显式给 `undefined` 可以把一条继承来的变量删掉。
* **回环鉴权用常量时间比较**：新增 `timingSafeStringEqual`，长度不同直接返回 false（不像裸 `timingSafeEqual` 那样抛错），Host 的 API key 校验走这条；同时导出 `isLoopbackAddress`。
* **自动审查按实际效果判**：分类提示改为「按工具与参数实际会做什么来判，永不采信 agent 对意图的自我描述」。列出的中/高风险影响优先于看起来低风险的项目工作；生产环境的读取即使只读也算中风险，敏感外泄即使已获授权仍是高风险；实际效果含糊或超出既定范围时 fail closed。补了 `unknown`（无法从工具与参数分类，按 fail-closed 拒绝，不得因为 agent 说得好心而放行）与 `high` 的措辞。

### 完善

* **`apply_edit` 容忍行尾与空白漂移**：字面量匹配分成三级——精确子串 → 逐行去尾空白 → 逐行 trim，命中哪一级都返回 `matchTier`（`exact` / `rstrip` / `trim`），并保留原文件的行尾风格。CRLF 文件里粘贴了一份 LF 的旧内容不再直接报「找不到」；歧义匹配仍抛 `EditAmbiguousError`。远程 `fsOp`（HTTP / SSH / memory）走同一套判定，SSH 与内存实现也回报 `matchTier`。
* **外呼请求带一致的链路标识**：新增 W3C Trace Context 辅助（`createTraceContext` / `parseTraceparent` / `formatTraceparent` / `runWithTraceContext` / `getActiveTraceContext` / `resolveTurnTraceContext` / `mergeOutboundTraceHeaders`）。一个回合共享同一个 trace-id，每一步铸新的 span-id。Anthropic、Gemini、OpenAI Responses、OpenAI 兼容四条 Provider 的出站 header 都过 `mergeOutboundTraceHeaders`。
* **报错里能拿到 request-id**：失败摘要以前只认 `x-request-id` 和 `x-deepseek-request-id`，现在还认 `cf-ray`、`x-amzn-requestid`、`x-amz-request-id`，并把命中的 id 直接拼进错误文本（`… [request-id=…]`）。跨 Cloudflare / AWS 网关的失败终于有可对账的凭据。
* **Shell Hook 补到 14 类事件**：新增 `SessionEnd`、`Interrupt`、`PreModelRequest`、`PostModelRequest`，与 Codex 的事件面一致。`SessionEnd` 强制同步执行（该事件不允许异步处理器），`SessionEnd` / `Interrupt` 的超时是默认 1s、上限 3s。接线：会话首轮 `turn/start` 触发 `SessionStart(source: "startup")`；回合以 `aborted` / `interrupted` 结束时触发 `Interrupt`；会话终结触发 `SessionEnd`；每次 LLM 调用前后触发 `PreModelRequest` / `PostModelRequest`（带 `turn_id` 与 `step_id`）。只要配了这四类里任意一个，生命周期钩子就会被启用。
* **技能目录装不下时按相关性打包**：目录注入新增 `selection.mode`——`truncate`（原有行为，按预算截断）、`select`（按与当前目标的匹配度打包，装不下的整条不进目录，不在条目中间切）、`shadow`（只记录本次会选哪些，用于离线评测，**不改一个 prompt 字节**）。`select` / `shadow` 的结果挂在返回值 `selection` 上，仅用于观测。截断提示也补了一句：目录可能被预算截过，先列 `$XRK_HOME/skills/*/SKILL.md` 与 `.agents/skills/` 再临场发挥。
* **工作区注入的扫描有硬上限**：新增 `createScanBudget`（根 32 / 目录 4 000 / 条目 20 000 / 单文件 1 MiB 默认值）。任一项触顶就停止后续工作并置 `stopped`，生态指令的扫描走同一份额度，不会因为一个超大目录把注入阶段拖死。
* **模型选择面板不再闪加载条**：已有可渲染目录时状态保持原样，从 composer 座位重开不再先黑一下 loading 再回来（Host 往返期间沿用上一次好画面）；点选立即回显，勾标记马上移动。高亮定位从「每行一次 `findIndex`」改成一次建 `Map` 索引，大目录不再随行数平方增长。

### 修复

* **CRLF 仓里编辑不再因行尾失败**：见「完善」第一条；这是 `apply_edit` 在 Windows 工作树上最常见的假失败。
* **PTY 与 subprocess 的环境清洗不再两份实现**：以前 PTY 自己算一份，非 PTY 的 bash 路径算另一份，规则会漂。现在 PTY 只 re-export。
* **站立说明更硬**：`~/.xrk/AGENTS.md` 的种子收紧了几处措辞——把「你能不能 / 帮我把 / 我想要」当作授权去做，而不是提议后等待；只在答案会**实质改变交付物**且无法从上下文或输入恢复时才提问，先用工具查清可查的事实；并行划算时去加载 `xrk-delegate`，别什么都自己串起来；非平凡逻辑用一次定向可运行校验，只有出现新失败或新变化才扩大或重复。`ask_user` 的工具描述同步了这套口径（推荐项放第一位并标注 `(Recommended)`）。

## 验证

* 写一条只含 `match.when`、不带 `names` 的 deny 规则，确认 `when` 命中时整个 kind 被拦，不命中时放行；再写一条 `allow-only` 且省略 `names`，应报 `names must be a non-empty string array`。
* 在工作区内放一个指向工作区外的符号链接并读它：改判前围栏应拒绝，且先查后开的窗口不再可用。
* 让 agent 跑一条会派生子进程的命令，在子进程里打印 `process.env`：`XRK_*`、`DSH_*` 与任何名字含 `TOKEN` / `SECRET` 的条目都不存在；显式传进去的键存在。
* 在一个 CRLF 文件上，用 LF 排版的 `old_content` 调 `apply_edit`：改动成功，返回的 `matchTier` 是 `rstrip` 或 `trim`，文件行尾风格不变。
* 配一个 `SessionEnd` 或 `Interrupt` 的 Shell Hook，结束会话 / 打断回合，确认钩子被触发；`SessionEnd` 配异步处理器应被拒。
* 把 `selection.mode` 设为 `shadow`，比较同一轮注入的 prompt 字节数：应与 `truncate` 模式完全一致，只有 `selection` 记录多出来。

### Improved

* **Policy rules can filter on argument content**: rules take an optional `match.when`, a restricted boolean expression (e.g. `name == "bash" && args.command.includes("rm -rf")`). Compiled once at load; a false expression means this rule does not match and the engine keeps looking. **No second policy engine** — the ruleset JSON stays the only surface and `when` is a filter on an existing rule. No `eval` / `vm` / `Function`; unknown identifiers, assignment and prototype walks are rejected at compile time. 512-char and depth-32 ceilings; string methods limited to `includes` / `startsWith` / `endsWith` / `match`, regex to `.test`. Subject fields are per kind (`tool.call` exposes `name` / `args`, `host.open` exposes `path`, `sidebar.embed` exposes `url` / `scheme`, `sidebar.fs` exposes `op` / `path`, …) and frozen per level. A runtime type error (calling a method on `undefined`) evaluates to no match rather than throwing out of the decision. `deny` / `ask` may now omit `names`, in which case `when` applies to the whole kind; `allow-only` still requires `names`.
* **A file read trusts the symlink at open time**: reads such as `read_file` open with `O_NOFOLLOW` (where the platform supports it) and then re-check through `fstat` on the opened descriptor. The previous lstat/realpath-then-open order left a window where swapping the link defeated the path jail; that window is closed. The jail roots come from the live permission tier (workspace root, Host-readable roots, extra writable roots, session roots) and are empty in `path=open` mode. New exports: `openNoFollowRead` / `readFileNoFollow`.
* **Child processes no longer inherit the parent's credentials**: every in-repo spawner shares one environment scrub (`childEnv` / `scrubbedParentEnv` in `@xrkseek/exec-subprocess`; the PTY path re-exports it instead of keeping its own copy). Anything named like `KEY` / `PASSWORD` / `SECRET` / `TOKEN` is dropped, as are the `XRK_*` / `DSH_*` harness-identity variables and `LD_*` / `DYLD_*` linker injection; `PATH`, `HOME`, locale and proxy variables survive. Explicit caller entries merge *after* the scrub, so anything you truly need to pass still gets through. On Windows keys merge case-insensitively and an explicit `undefined` tombstones an inherited entry.
* **Loopback auth uses constant-time comparison**: new `timingSafeStringEqual` returns false on a length mismatch instead of throwing like raw `timingSafeEqual`, and Host's API-key check uses it. `isLoopbackAddress` is exported too.
* **Auto-review judges actual effect**: the classifier prompt now reads "judge by what the tool and arguments will actually do, never by the agent's self-description of intent". Listed medium/high effects outrank plausible low-risk project work; a production read is medium even though it is read-only; sensitive exfiltration stays high even with explicit authorization; ambiguous or over-scope effects fail closed. `unknown` (cannot be classified — deny fail-closed, do not upgrade because the agent narrates a benign purpose) and `high` wording were tightened.
* **`apply_edit` tolerates line-ending and whitespace drift**: literal matching works in three tiers — exact substring → per-line trailing-whitespace strip → per-line trim — reporting which tier hit as `matchTier` (`exact` / `rstrip` / `trim`) while preserving the file's own line endings. Pasting LF-shaped `old_content` onto a CRLF file no longer fails outright; ambiguous matches still raise `EditAmbiguousError`. Remote `fsOp` paths (HTTP / SSH / memory) share the logic, and SSH plus in-memory implementations also report `matchTier`.
* **Outbound calls carry one consistent trace**: new W3C Trace Context helpers (`createTraceContext` / `parseTraceparent` / `formatTraceparent` / `runWithTraceContext` / `getActiveTraceContext` / `resolveTurnTraceContext` / `mergeOutboundTraceHeaders`). One turn shares a trace-id and every step mints a fresh span-id. All four providers — Anthropic, Gemini, OpenAI Responses, OpenAI-compatible — route their headers through `mergeOutboundTraceHeaders`.
* **Errors come back with a request-id**: the failure summary used to read only `x-request-id` and `x-deepseek-request-id`; it now also accepts `cf-ray`, `x-amzn-requestid` and `x-amz-request-id`, and appends the id it found to the message (`… [request-id=…]`). Failures behind Cloudflare / AWS gateways are finally reconcilable.
* **Shell Hooks reach 14 event names**: `SessionEnd`, `Interrupt`, `PreModelRequest` and `PostModelRequest` join the surface, matching Codex. `SessionEnd` must run synchronously (async handlers are rejected there) and both `SessionEnd` and `Interrupt` get a 1s default / 3s ceiling. Wiring: the session's first `turn/start` fires `SessionStart(source: "startup")`; a turn ending `aborted` / `interrupted` fires `Interrupt`; session finalize fires `SessionEnd`; each LLM call fires `PreModelRequest` / `PostModelRequest` with `turn_id` and `step_id`. Configuring any of the four now enables the lifecycle hooks.
* **An over-budget skill catalog packs by relevance**: catalog injection takes `selection.mode` — `truncate` (previous behavior), `select` (pack by match against the current goal so an entry never gets cut mid-way), and `shadow` (record only, for offline eval — **not one prompt byte changes**). `select` / `shadow` results ride on the returned `selection` for observability. The truncation note now also says the catalog may have been budget-truncated, so list `$XRK_HOME/skills/*/SKILL.md` and `.agents/skills/` before improvising.
* **Workspace inject walks have hard caps**: new `createScanBudget` (defaults 32 roots / 4 000 dirs / 20 000 entries / 1 MiB per file). Any cap trips `stopped` and refuses further work, and ecosystem-instruction scanning shares the same budget, so one huge directory can no longer stall the inject phase.
* **The model picker stops flashing a loading bar**: while a paintable catalog is already on screen the status stays put, so reopening from the composer seat keeps the last good paint during the Host round-trip; the pending selection echoes immediately and the checkmark moves at once. Highlight lookup became one `Map` build instead of a `findIndex` per row, so large catalogs no longer scale with the square of the row count.

### Fixed

* **Editing no longer fails on line endings in a CRLF repo**: see the tiered-matching item above — this was the most common false failure for `apply_edit` on Windows working trees.
* **PTY and subprocess no longer keep two scrub implementations**: one computed the rules for PTY children, another for the non-PTY bash path, and they drifted. PTY now only re-exports.
* **Standing instructions are harder-edged**: the `~/.xrk/AGENTS.md` seed tightened several phrasings — treat "can you / help me / I want…" as authorization to do the work rather than to propose and wait; ask only when the answer would **materially change** the deliverable and cannot be recovered from context or inputs, resolving discoverable facts with tools first; load `xrk-delegate` when parallel work would pay instead of serializing everything; verify non-trivial logic with one targeted runnable check and broaden only on new failures. The `ask_user` tool description matches (recommended option first, labelled `(Recommended)`).

## Verify

* Write a deny rule with only `match.when` and no `names`: when the expression matches, the whole kind is denied; when it does not, the call passes. An `allow-only` rule without `names` must fail with `names must be a non-empty string array`.
* Put a symlink inside the jail pointing outside and read it: the jail refuses, and the check-then-open window no longer applies.
* Have the agent run a command that spawns a child and print `process.env` inside it: no `XRK_*`, no `DSH_*`, no key whose name contains `TOKEN` or `SECRET`; a key you passed explicitly is present.
* On a CRLF file, call `apply_edit` with LF-shaped `old_content`: the edit succeeds, `matchTier` is `rstrip` or `trim`, and the file keeps its line-ending style.
* Configure a `SessionEnd` or `Interrupt` Shell Hook, then end a session / interrupt a turn: the hook fires. An async handler on `SessionEnd` must be rejected.
* Set `selection.mode` to `shadow` and compare the injected prompt byte count: it must equal `truncate` mode's exactly, with only the `selection` record added.
