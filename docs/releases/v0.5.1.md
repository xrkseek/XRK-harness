# v0.5.1

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.5.0](./v0.5.0.md)：补回冲掉的产品面（连接相位 chrome · 概况工具区 · 图生预览 · 文件夹拖入路径），收紧 Desktop Host 门闩与工具 dataURL 体积，并建议侧栏 **`xrkh-better-sidebar@0.18.20`**（终端 resize 不再刷版本 MOTD）。

Relative to [v0.5.0](./v0.5.0.md): restores washed product surface (connection-phase chrome · Overview utilities · image-gen preview · folder-drop as path), tightens Desktop Host gating and tool dataURL size, and prefers sidebar **`xrkh-better-sidebar@0.18.20`** (resize no longer reprints the version MOTD).

### 完善

* 完善 Desktop **`waitUntil` / `whenHostReady`**：`xrk-app:` 下 Face 握手等 Host Fetch 附着后再走，减少空转进 `retry:backoff`。
* 完善连接指示与 Settings 页脚 **`connectionPhase` chrome**（握手阶段文案替代笼统「连接中」）。
* 完善概况 Status **工具区**：会话日志导出与 Open in App 回到 `details.status.utilities`（与 Desktop 标题栏职责分离）。
* 完善 Open in App：**等 Host 连上并 `canOpenPath` 就绪**后再探目录，避免闪屏期一次失败清空列表。
* 完善插件清单安装 UI：**跨模态 remount 保留** TerminalBlock / 成功态 /「需刷新客户端半部」提示。
* 完善图生/视频工具卡与 **文件卡**（`tool.call.images|files`）预览接线；大体积 dataURL 在工具参数投影中脱敏截断。
* 完善对话 **文件夹拖入**：按本机路径 chip 摄入（Desktop `pathForFile`），不再走 FileReader 误报。
* 完善 Desktop 标题栏：窗控固定视口右上，侧栏布局推挤不再顶开窗控。
* 完善 `package:desktop`：stage 保留构建工具链（`--prod=false`），避免 CI/产包后缺 `tsc`。
* 完善 Host **打断后续写**：`autoContinue` 默认开启（显式 `false` 才关）。

### 修复

* 修复 0.5.0 发版前 stash 未完整合回导致的 **连接相位 / Boot chrome / 概况按钮 / 图生预览 / 插件安装 session** 等产品面缺失。
* 修复工具调用把整段 **image dataURL** 塞进可见参数导致的卡顿与噪音。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.5.1`**（接管 npm `@latest`）；npmjs 保留 **0.5.1** 与回退钉 **0.3.11**。
* 标准侧栏建议 **`xrkh-better-sidebar@0.18.20`**（独立 npm 包；见该包 README）。

## 安装

```bash
npm i -g @xrkseek/harness-cli@0.5.1
xrkh web
```

侧栏（可选）：

```bash
xrkh plugin add xrkh-better-sidebar@0.18.20
xrkh restart
```

然后硬刷新客户端半部。

## 验证

* Desktop：闪屏相位文案后进入产品壳；开终端不切断 Host；拖拽分栏不反复弹 Windows 版本 MOTD。
* 概况工具区可见「资源管理器 / 会话日志」类入口；图生工具有预览卡且参数区无巨型 dataURL。
* 拖入文件夹变为路径 chip，可随消息发送。

---

### Improved

* Desktop **`waitUntil` / `whenHostReady`**: Face handshake waits for Host Fetch attach on `xrk-app:` before spinning into `retry:backoff`.
* Connection indicator + Settings footer **`connectionPhase` chrome** (stage labels instead of a generic “connecting”).
* Overview Status **utilities**: session-log export and Open in App back on `details.status.utilities`.
* Open in App: probe only after Host is connected and `canOpenPath` is ready.
* Plugin-install UI session: survive Settings modal remounts (TerminalBlock / success / client-refresh hint).
* Image/video gen cards + **file cards** (`tool.call.images|files`) preview wiring; large dataURLs redacted in tool-arg projection.
* Conversation **folder drop** as a local path chip (Desktop `pathForFile`), not a FileReader failure.
* Desktop titlebar: window controls stay viewport-fixed so sidebar layout-push cannot shove them.
* `package:desktop`: keep the build toolchain (`--prod=false`) so CI/pack does not lose `tsc`.
* Host **post-interrupt continue**: `autoContinue` on by default (opt out with explicit `false`).

### Fixed

* Restored product surface washed by an incomplete post–0.5.0 stash restore (connection phase / Boot chrome / Overview buttons / image-gen preview / plugin-install session).
* Stopped shipping full **image dataURLs** inside visible tool-call args.

### Other changes

* Public line **`@xrkseek/harness-cli@0.5.1`** takes npm `@latest`; npmjs keeps **0.5.1** and rollback pin **0.3.11**.
* Prefer sidebar **`xrkh-better-sidebar@0.18.20`** (separate npm package; see that package README).

## Install

```bash
npm i -g @xrkseek/harness-cli@0.5.1
xrkh web
```

Optional sidebar:

```bash
xrkh plugin add xrkh-better-sidebar@0.18.20
xrkh restart
```

Then hard-refresh the client half.

## Verify

* Desktop: splash phase copy then product shell; opening a terminal does not kill Host; split-drag does not reprint the Windows version MOTD.
* Overview utilities show explorer / session-log style actions; image-gen shows a preview card without huge dataURLs in args.
* Dropping a folder becomes a path chip that can send with the message.
