# v0.4.2

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

**补丁号，只动一处**：Windows 桌面 computer use 的 UIA provider（`@xrkseek/exec-computer-use`）。此前它"能抓到东西"，但抓到的东西**不可信**——中文窗口名是乱码、`100%(cash)` 被当成修饰键序列、目标程序停止泵消息时整条工具调用**永久挂起**。本版把这些修成可验证的行为，公共 API 与配置面**没有破坏性变更**。

A patch release touching one seam: the Windows UIA provider behind `computer_use`. It could already read the accessibility tree, but the tree lied — CJK element names came back mangled, literal text like `100%(cash)` was parsed as SendKeys modifier sequences, and a target app that stopped pumping messages hung the tool call forever. Twelve regression tests now pin the corrected behavior.

---

## 一、修了什么 / What was broken

| 症状（模型看到的）                                      | 机制（真实原因）                                                                            | 修法                                                                                                              |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 中文窗口名 / 元素 `Name` 全是乱码                       | Windows PowerShell 5.1 的 stdout 走 **OEM 码页**（zh-CN 为 GBK），Node 端按 UTF-8 解码      | 脚本前置 `PS_PRELUDE` 把 `OutputEncoding` / `ErrorEncoding` 钉成 UTF-8，JSON 往返不再腐坏                         |
| 输入含 `%` `(` `)` `{` `+` `^` 的文本，结果串了或字被吞 | SendKeys 的保留字符：`+^%(){}[]` 是修饰键与序列语法                                         | `escapeSendKeys()` 逐字符 `{…}` 包裹；**非 ASCII 不进 SendKeys**，改走 `Set-Clipboard` + 粘贴                     |
| 工具调用**不返回**，会话卡在那一步                      | 目标 app 不再泵 UIA 消息时 `FindAll` 无限阻塞，provider 没有上界                            | `DEFAULT_POWERSHELL_TIMEOUT_MS = 25_000` + 单次结算（`settled`）；超时 `kill()` 子进程并回 `COMPUTER_USE_BACKEND` |
| `app: "WeChat"` 打错字只得到"没找到"                    | 不匹配时不回报任何上下文                                                                    | 过滤不匹配时**返回当前打开的窗口列表**，模型可自我纠正后再试                                                      |
| 某些 app 抓回来是**空树**                               | 首趟只走 `TreeScope.Children`，未渲染的元素拿不到                                           | 空树自动**带 offscreen 节点重试一次**；offscreen 元素丢弃 bounds（避免模型点空）                                  |
| 元素坐标出现负数 / 荒谬大值                             | 直接把 `double` 矩形强转 `[int]`，溢出与 NaN 不检查                                         | `XrkSafeInt` 守卫：NaN / Infinity / 越界 → `null`                                                                 |
| `list_windows` 恒空                                     | UIA 返回的是可枚举包装对象，被当数组读（`{value, Count}`）                                  | 解包后再读                                                                                                        |
| 偶发 `spawn powershell.exe ENOENT`                      | 只写裸名，依赖父进程 PATH 含 `System32\WindowsPowerShell\v1.0`；GUI / 服务父进程常被裁 PATH | 从 `SystemRoot` 解析绝对路径，找不到再回落裸名。刻意不用 `pwsh` 7：UIAutomation 程序集只随 5.1 安装               |
| 过滤串里带 `'` 或 `$` 时脚本被破坏                      | 字符串按双引号内插进 PowerShell，`$` 被展开、裸 `'` 截断脚本                                | `psStr()` 一律以**单引号字面量**嵌入并转义                                                                        |

## 二、为什么不是提示词补丁 / Structure over prompt text

同上一条补丁号的原则：**能在结构上消除的，不写进提示词**。转义、超时、解包全部落在 provider 的**唯一出口**上——不是每个调用方各写一遍，也不是叮嘱模型"不要输入特殊字符"。模型不应该知道 SendKeys 的保留字，正如它不应该知道会话标记长什么样。

## 三、兼容性与边界 / Compatibility

- **无破坏性变更**：`ComputerUseService` 形状不变（`capture` / `act` / `listWindows`）；provider 选项新增可选 `timeoutMs`。
- 新增导出 `mapKeysToSendKeys`、`escapeSendKeys`（供测试与第三方 provider 复用）。
- 仍然是 **opt-in**：`XRK_COMPUTER_USE=1` 或 Settings → Plugins → Computer use（`mode=uia`）；未配置时工具照常注册、执行时诚实失败（与 LSP 同一策略）。
- 网页页面请继续用 `browser_*`，`computer_use` 只留给原生桌面应用。

## 四、测试锁住 / Tests

`packages/exec/computer-use/tests/computer-use.test.ts` 新增 12 条，覆盖：`captureScript`（整数溢出守卫与 CJK 编码前置、过滤串按单引号字面量嵌入）、provider hardening（解包窗口列表、过滤不匹配时回报窗口、空树带 offscreen 重试、越界丢弃 bounds、type 回落路径转义标点与引号、卡死脚本超时而非挂死）、`escapeSendKeys`（保留字符全包裹）。

## 五、升级 / Upgrade

```bash
npm i -g @xrkseek/harness-cli@0.4.2
xrkh web
```

无需迁移：配置面、插件契约、会话日志格式均未变。**旧 Host 需重启**才会加载新 provider——运行中的进程仍持有旧实现（表现为中文乱码与卡死依旧）。
