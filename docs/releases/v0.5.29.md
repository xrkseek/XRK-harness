# v0.5.29

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.5.28](./v0.5.28.md)：社区模型（Our Free Model · WorkBuddy · pi-ai 声明源）的**思考档位**一路打通到模型选择器；工具行展开真正跟随设置；缓存命中率口径修正。

Relative to [v0.5.28](./v0.5.28.md): reasoning-effort menus now travel from community adapters all the way into the model picker; chat tool rows follow the Settings expand preference; the cache-hit readout is measured against the right denominator.

### 新增

* **社区模型思考档位贯通**：`community-llm-host-sync` 新增 `resolveModel` 增补与 `reasoningFromUnknown`，识别 Cordis `{efforts, defaultEffort}`、DSH pi-ai `reasoningEfforts` 字典（`false` = 不支持）、`thinkingLevelMap`（`null` = 未开放）与字符串数组四种写法；档位随 Face 同步进 `llm-pi-ai` 并出现在模型选择器。
* **同步指纹升到 c2**：指纹带上档位清单，档位变化会真正重新同步（此前只按模型 id 去重）。
* **手改 pi-ai 配置也读档位**：`model-catalog` 解析 settings 行的 reasoning；声明型 provider 改为回读 profile 模型，`reasoning` / 软预算字段不再被瘦身的 inventory 形状丢掉。

### 修复

* **修复工具行展开开关不生效**：`ui-tool` 改为在 cordis `inject` 上等 `conversationUiPrefs`，不再在 apply 期兜一个 Settings 永不写入的孤儿 store；`useToolExpandState` 让展开态跟随设置 hydrate，手动折叠/展开后以用户为准。
* **修复「缓存命中」百分比偏低**：分母改为 `uncachedInputTokens + cacheReadTokens`，缓存写入（预填充）不再算作未命中。
* **修复 `/plugins/*` 无扩展名路径提前 404**：Cordis / dsh-compat 的 status / probe 等宿主 API 面不再被静态服务终结，交回后续处理器应答。
* **修复 Cordis stub 状态误报**：面板状态判断改看宿主半部是否真的 apply 过（`isCordisHostApplied`），仅暂存 client.js 不再算已桥接。
* **修复 Desktop 布局下 User-Agent 版本号**：`xrk-llm` 版本解析同时尝试 `../package.json` 与 `../../package.json`，避免命中构建期 `lib/package.json` 或读不到。

### 完善

* **完善 community LLM 同步类型**：host / adapter / Face 三处模型行都带 `reasoning` 字段（efforts + defaultEffort）。
* **完善测试**：新增 `community-llm-host-sync.test.ts` 覆盖四种 reasoning 形态；补 `apply-prefs-race` 接线用例、`terminal-card` hydrate 用例、模型目录 reasoning 用例。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.5.29`**（接管 npm `@latest`）。
* Desktop 私有壳版本对齐 **0.5.29**；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。

---

### Added

* **Community reasoning efforts end-to-end**: `community-llm-host-sync` gains `resolveModel` enrichment plus `reasoningFromUnknown`, understanding Cordis `{efforts, defaultEffort}`, the DSH pi-ai `reasoningEfforts` dict (`false` = unsupported), `thinkingLevelMap` (`null` = not offered) and string arrays; efforts ride the Face sync into `llm-pi-ai` and the model picker.
* **Sync fingerprint bumped to c2**: the fingerprint carries the effort menu so a changed menu actually re-syncs (previously only model ids deduped).
* **Hand-edited pi-ai configs get efforts too**: `model-catalog` parses reasoning from settings rows, and declared providers re-read their profile models so `reasoning` / soft-budget fields survive the thinner inventory shape.

### Fixed

* **Tool-row expand preference now applies**: ui-tool waits on `conversationUiPrefs` through cordis `inject` instead of capturing an orphan store Settings never writes; `useToolExpandState` follows the hydrate but yields to a manual toggle.
* **Cache-hit readout too low**: the denominator is now `uncachedInputTokens + cacheReadTokens`, so cache writes (prefill) no longer count as misses.
* **Extensionless `/plugins/*` paths no longer terminal-404**: Cordis / dsh-compat status and probe surfaces fall through to later handlers.
* **Cordis stub status misreport**: panel status now checks whether the host half actually applied (`isCordisHostApplied`) instead of counting a staged client.js.
* **User-Agent version in the Desktop layout**: `xrk-llm` tries both `../package.json` and `../../package.json`, so it no longer hits a build-time `lib/package.json` or finds nothing.

### Improved

* Community LLM sync types carry `reasoning` (efforts + defaultEffort) on host / adapter / Face model rows.
* Tests: new `community-llm-host-sync.test.ts` covers the four reasoning shapes; added the `apply-prefs-race` wiring case, a `terminal-card` hydrate case, and model-catalog reasoning cases.
