# v0.6.2

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.1](./v0.6.1.md)：技能可以选写到当前工作区还是本机全局；干员升到全局后只留一份名单；给子代理跟进时默认立刻插话；等子代理时不再误显示「已中断」；重启后再聊不会把轮次从「第 1 轮」重数。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.2`。

Relative to [v0.6.1](./v0.6.1.md): skills can land in the current workspace or your home global tree; promoting a teammate to global keeps one roster home; child follow-ups default to immediate steer; waiting on a child no longer looks Interrupted; resumed sessions keep their round numbers. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.2`.

### 新增

* **提议技能可选落点**：默认写到**当前会话工作区** `.agents/skills/<name>/`；`scope=global` 写到本机 `~/.agents/skills/<name>/`（各工作区都能用）。写错 scope 会直接报错，不会悄悄改成工作区。仍要你在弹窗里批准后才落盘。
* **干员和技能分开说**：要加人 / 干员 / teammate → 走团队保存；提议技能只写一份 `SKILL.md`。工具说明里也写清了中文说法，避免混着说时走错。

### 完善

* **干员升到全局只留一份**：提升后会清掉**所有**工作区名单里的同名条目，别的仓库残留行不再盖住全局纪录。在某个工作区本地改动仍只影响那份画布。
* **跟进子代理默认插话**：`send_message`、团队广播不写投递方式时，立刻插到对方下一个工具步；想等它空闲再送，再显式选排队。对方忙时的提示也只说插话，不再让人以为根本送不进去。
* **后台委派何时结束本回合**：子代理做完后，Host 会把完成通知插回本会话。本回合若没有别的事，可以结束等那条通知；只有下一步马上要用结果时，再继续等着。

### 修复

* **重启后再聊，轮次接着数**：崩溃或重启后打开已有历史的会话，「第 N 轮」会接着旧日志往下数，不再从「第 1 轮」重来，并与侧栏统计一致。
* **等子代理时不再显示「已中断」**：等待期间那一行保持运行中（扫描动效仍在），与「深潜中」一致；真正停掉或整轮结束后才标中断。
* **多工作区下提议技能写对仓**：技能落到**当前会话**所在工作区，不会一律写到启动 Host 时的那个仓。
* **非法 scope 直接拒绝**：干员或技能里写错 scope 会报错，不再被悄悄改成工作区。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.6.2`**（接管 npm dist-tag **`@latest`**）；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。
* Desktop 更新源同步 win-x64 未签名测试包 `xrk-harness-0.6.2-win-x64.exe`。
* 教科书同步：`docs/skills-layers.md` · `docs/modules/session-projection.md`。

## 验证

* 提议技能默认落在当前会话工作区；带 `scope=global` 落在 `~/.agents/skills/`；乱写 scope 应报错。
* 在 B 工作区的会话里提议技能，文件应出现在 B，而不是启动 Host 的那个仓。
* 把干员提升到全局后，在其它工作区列表里也应看到全局那份，不被旧行盖住。
* 后台派出子代理后本回合无事可做就结束；完成后通知以插话回到本会话；跟进消息不写投递方式即走插话。
* 接着一个已有 3 轮历史的会话聊，新一轮应是「第 4 轮」。
* `wait_agent` 等待期间，聊天与轨迹里该行保持运行态，不是「已中断」。

---

### Added

* **Skill proposals choose where to land**: default is the **current session workspace** `.agents/skills/<name>/`; `scope=global` writes `~/.agents/skills/<name>/` for every workspace. A bad scope errors out instead of silently becoming workspace. The Face approval dialog still gates the write.
* **Teammates and skills are described apart**: adding a 干员 / member / teammate uses team save; proposing a skill only writes one `SKILL.md`. Chinese aliases sit in the tool descriptions so mixed-language requests stop routing wrong.

### Improved

* **Promoting to global keeps one home**: every workspace roster drops that id, so a leftover row in another repository cannot shadow the global record. Workspace edits still only touch that canvas.
* **Child follow-ups default to steer**: omitted delivery on `send_message` and team announce lands at the child’s next tool step; queue is the explicit “wait until idle”. Busy-child copy only points at steer.
* **When to end after a background handoff**: Host steers a completion notice back. End the turn if nothing else is useful; keep waiting only when the next step needs the answer.

### Fixed

* **Resumed sessions keep round numbers**: after a crash or restart, 「第 N 轮」 continues from the durable log instead of restarting at 第 1 轮, in line with sidebar stats.
* **Waiting on a child no longer looks Interrupted**: the row stays running while the turn is open; Interrupted only after a real stop or a closed turn.
* **Multi-workspace skill proposals hit the right tree**: the file lands under the **current session’s** workspace, not whichever repo started the Host.
* **Bad scope values are refused**: typos error as invalid instead of being rewritten to workspace.

### Other changes

* Public line target **`@xrkseek/harness-cli@0.6.2`** (takes over npm dist-tag **`@latest`**); `apps/cli` / `apps/desktop` / `packages/sdk` move together.
* Desktop update feed synced with the win-x64 unsigned test build `xrk-harness-0.6.2-win-x64.exe`.
* Textbook sync: `docs/skills-layers.md` · `docs/modules/session-projection.md`.
