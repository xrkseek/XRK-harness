# v0.6.2

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

**`0.6.x` 线第二个补丁**：相对 [v0.6.1](./v0.6.1.md)，这一轮都在**协作与投影的边界条件**上：`propose_skill` 终于能落到你想要的那棵树、Agent Team 干员提升到 global 不再被别的工作区残留行遮蔽、子代理跟进出默认改**插话**、`wait_agent` 期间工具行不再被画成「已中断」、崩溃或重启后接着聊的会话不再从「第 1 轮」重新开始。npm dist-tag **`@latest`** 由 `@xrkseek/harness-cli@0.6.2` 接管。

**Second patch on the `0.6.x` line**: relative to [v0.6.1](./v0.6.1.md) this round works the **edges of collaboration and projection** — `propose_skill` can finally land in the tree you meant, promoting an Agent Team member to global is no longer shadowed by a leftover row in another workspace, following up with a child defaults to **steer**, a `wait_agent` call is no longer painted Interrupted while its turn is open, and a session resumed after a restart no longer restarts its round counter at 第 1 轮. npm dist-tag **`@latest`** now points at `@xrkseek/harness-cli@0.6.2`.

### 新增

* **`propose_skill` 带 `scope`**：`workspace`（默认）写**当前会话工作区** `.agents/skills/<name>/`，`scope=global` 写用户主目录 `~/.agents/skills/<name>/`（`defaultGlobalSkillsRoot`，刻意**不是**产品 `~/.xrk` 树）。其它值直接 `invalid-payload` 拒绝，不再静默回落到 workspace；仍由 Face 确认弹窗把关，批准后才落盘。`docs/skills-layers.md` 中英两半同步。
* **干员与技能彻底分开表述**：`subagent` / `team_list` / `team_save` / `team_graph` 与 harness preset 站立文案统一写明「用户说 干员 / 成员 / teammate / 想进子代理团队 → `team_save`；`propose_skill` 只写一份 SKILL.md」，并把中文别名放进工具描述里，避免中英混说时再次走错。

### 完善

* **Agent Team 提升到 global 是「一个家」**：`set(scope=global)` 现在枚举**所有**工作区 roster 文件并删掉同名 id（此前只清当前画布那一份），别的仓库里残留的工作区行不再继续遮蔽全局记录；`list` / `get` 仍按 global 优先、工作区覆盖的口径读。工作区 scope 只写自己那份画布。
* **子代理跟进默认插话**：`send_message` 与 `team_graph announce` 的缺省投递由 `queue` 翻成 **`steer`**（下一个工具步 / 回合边界落地），`queue` 变成「等子代理空闲」的显式选择。忙碌子代理的拒绝文案只再建议 `delivery=steer`——旧的「用 wait_agent 或 steer」会让人误以为排队投递根本送不进去。Overview 舰队告警同步改成 `(steer/interrupt)`。
* **交接文案给出结束条件**：背景 spawn 的回执不再只说「继续干活、别轮询」，而是写明「子代理落定后 Host 会把完成通知插进本会话；本回合若没有别的可做就结束等那条通知；若这一步就要答案用 `wait_agent`」。`interrupt_agent` 的说明同样从「子会话没有消失」改为「正在运行、会 steer 回来」，并保留「先读它再决定是否重派」。

### 修复

* **修复崩溃 / 重启后接着聊显示「第 1 轮」**：`FaceWireIdMaps` 的轮次号是懒分配的，Host 重启或会话被 LRU 驱逐之后，进程看到的**第一条** `turn/start` 就被编成 wire `1`。壳侧「第 N 轮」按这个 wire 号显示，而 `turnOutline` 与 `sessionStats` 早已折进整段日志——于是新回合顶着「第 1 轮」的标签、统计却按全量算。历史分页本来就会先预分配，实时路径缺同款守卫；新增 `isPrimed()`，未预分配过的会话在第一条实时 append 前按持久日志 prime。撤掉守卫后钉子测试报 `[1, 1]`（持久日志应为 `[4, 5]`）。
* **修复 `wait_agent` 期间工具行显示「已中断」**：聊天工具节点与轨迹视图都拿 `step.status === "closed"` 当「工具结束」，可 step 关闭而所属 turn 仍打开是 `wait_agent` 挂着等子代理的正常形状——结果那一行画成 Interrupted，运行中扫描还被停掉，而 Host 侧仍显示深潜中，两个面板互相矛盾。现统一要求**拥有它的 turn 已闭合**才返回结束时间，聊天与轨迹同规则，同一行不会在两个页签读出不一致。
* **修复多工作区 Host 下 `propose_skill` 落错仓**：旧实现读的是运行时构造时捕获的单个 `options.workspaceRoot`，即谁启动了 Host 就写进谁的工作区。现改为调用时经 `resolveSessionCwd` 解析**本会话**工作区根。
* **修复非法 scope 被静默改写**：`parseRosterScope` 旧时把任何非 `global` 的值都折成 `workspace`，打错字或传错档就默默写到另一处。现返回 `undefined`，由 Face 三个 handler 与工具绑定各自以 `invalid-payload` 拒绝。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.6.2`**（接管 npm dist-tag **`@latest`**）；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。
* Desktop 更新源同步 **win-x64 未签名测试包** `xrk-harness-0.6.2-win-x64.exe`（先传 exe/blockmap 再传 `nightly.yml` / `latest.yml`）。
* 教科书同步：`docs/skills-layers.md`（propose_skill 双 scope + 干员走 team_save）· `docs/modules/session-projection.md`（wire `turn` 由「历史分页前预分配」扩为「历史分页前 + 冷启动后第一条实时 append」）。

### Added

* **`propose_skill` takes a `scope`**: `workspace` (default) writes `<current session workspace>/.agents/skills/<name>/SKILL.md`, `scope=global` writes under the user home `~/.agents/skills/<name>/` (`defaultGlobalSkillsRoot`, deliberately **not** the product `~/.xrk` tree). Anything else is refused as `invalid-payload` instead of silently falling back, and the Face approval dialog still gates the write. `docs/skills-layers.md` updated in both halves.
* **Members and skills are now described as different things**: `subagent`, `team_list`, `team_save`, `team_graph` and the harness standing prompt all say that a 干员 / 成员 / teammate / someone on the subagent team is `team_save`, while `propose_skill` only writes a SKILL.md — with the Chinese aliases inside the descriptions so a mixed-language request stops routing wrong.

### Improved

* **Promoting to global means one home**: `set(scope=global)` now enumerates **every** workspace roster file and drops the same id from all of them (it previously cleared only the current canvas), so a leftover workspace row in another repository can no longer shadow the global record. `list` / `get` keep the global-first, workspace-overlays order. Workspace scope still writes only its own canvas.
* **Child follow-ups default to steer**: the omitted `delivery` for `send_message` and `team_graph announce` flipped from `queue` to **`steer`** (lands at the child's next tool-step / turn boundary), and `queue` is now the explicit "wait until idle". The busy rejection only suggests `delivery=steer` — telling the model to "use wait_agent or delivery=steer" made the queued path look unreachable. The Overview fleet alert reads `(steer/interrupt)` to match.
* **Handoff copy states when the turn should end**: a background spawn no longer just says "keep working, do not busy-poll"; it says the child's result arrives as a Host completion notice steered into this session, to end the turn if nothing else is useful, and to call `wait_agent` when the next step needs the answer. `interrupt_agent` says the child is running and will steer back rather than "is not gone", and keeps the advice to read it before spawning a replacement.

### Fixed

* **A resumed session no longer restarts its round counter**: `FaceWireIdMaps` numbered turns lazily, so after a Host restart or LRU eviction the first `turn/start` the process saw became wire `1`. The shell keys 「第 N 轮」 off that number while `turnOutline` and `sessionStats` had already folded the whole log — the new round wore a 第 1 轮 label over full history. History pages already primed before wiring; the live path had no such guard. Adds `isPrimed()` and primes from the durable log on the first append of an unprimed session. Removing the guard makes the pin report `[1, 1]` where the durable log says `[4, 5]`.
* **`wait_agent` is no longer painted Interrupted**: the chat tool node and the trajectory view both treated `step.status === "closed"` as a finished tool call, but a closed step inside an open turn is exactly what a pending `wait_agent` looks like. The row read Interrupted, the running sweep stopped, and Host still reported the session diving — two tabs contradicting each other. Both surfaces now require the owning turn to be closed before returning an end time, so one row cannot read differently in chat and trajectory.
* **`propose_skill` no longer targets the wrong repository under a multi-workspace Host**: it used a single `options.workspaceRoot` captured when the runtime was constructed, so whichever workspace booted the Host received every proposal. The root now resolves per session via `resolveSessionCwd` at call time.
* **Bad scope values are no longer rewritten**: `parseRosterScope` used to fold anything that was not `global` into `workspace`, so a typo quietly wrote to the other home. It now returns `undefined`, and the three Face handlers plus the tool bindings refuse with `invalid-payload`.

### Other changes

* Public line target **`@xrkseek/harness-cli@0.6.2`** (takes over npm dist-tag **`@latest`**); `apps/cli` / `apps/desktop` / `packages/sdk` move together.
* Desktop update feed synced with the **win-x64 unsigned test build** `xrk-harness-0.6.2-win-x64.exe` (exe/blockmap first, then `nightly.yml` / `latest.yml`).
* Textbook sync: `docs/skills-layers.md` (propose_skill dual scope + members go to team_save) · `docs/modules/session-projection.md` (wire `turn` priming extends from "before any history page" to "before any history page and on the first live append after a cold start").
