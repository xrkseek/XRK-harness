# v0.5.13

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.5.12](./v0.5.12.md)：`glob` / `grep` 默认改走打包的 **`@vscode/ripgrep`**（认 `.gitignore`、`--json` 流式、命中上限即杀进程），二进制缺失时回退进程内遍历（跳过生成树、每 48 个条目让出事件循环）；`read_file` 读普通文本只按 `maxBytes` 读盘，不再把整份源文件塞进内存；后台 job 的 stdout/stderr 在 Host 内只保留 **256 KiB 尾**，超顶写进 `{XRK_HOME}/spill` 落盘文件、`job_output` 直接给出可 `read_file` 的路径，job 被裁剪时连带删除；子进程管道按块 `pause` + `setImmediate(resume)` 让路，spawn 出的子进程降为 `PRIORITY_BELOW_NORMAL`；Face 的 WS 发送队列按 `sessionId` 分车道 round-robin，一路刷屏不再卡住别的会话；文件工具的**绝对路径**可读可写面默认扩到产品家目录 `{XRK_HOME}`，相对路径仍锁在工作区，`extraWritableRoots` 进了 Settings 的 `permission` 命名空间（schema uid 5 → 7）；产品站立文件不再往工作区里 `mkdir .xrk`；子会话 Overview 的**委派方 seat** 现在跟主会话的真实节拍（`parentDelivery`），team graph 的根节点也会随子线路亮成 running。

Relative to [v0.5.12](./v0.5.12.md): `glob` / `grep` now run on the packaged **`@vscode/ripgrep`** by default (native ignore rules, streamed `--json`, killed at the hit cap) and fall back to an in-process walk (generated trees skipped, event loop yielded every 48 entries) when the binary is missing; `read_file` reads plain text by `maxBytes` from disk instead of pulling the whole source into memory; background-job stdout/stderr keep only a **256 KiB tail** in the Host and spill the overflow to `{XRK_HOME}/spill`, with `job_output` handing back a path `read_file` can open — deleted when the job is pruned; child pipes `pause` per chunk and `setImmediate(resume)` so other sessions interleave, and spawned children are dropped to `PRIORITY_BELOW_NORMAL`; the Face WS send queue round-robins per `sessionId` lane so one burst cannot stall the others; the file tools' **absolute-path** read and write surface now defaults to product home (`{XRK_HOME}`) while relative paths stay workspace-bound, and `extraWritableRoots` moved into the Settings `permission` namespace (schema uid 5 → 7); product standing files no longer `mkdir .xrk` inside the workspace; a child Overview's 委派方 seat now follows the home session's real beat (`parentDelivery`), and the team graph's root node lights up when a child line is running.

### 新增

* 新增 `packages/exec/fs/src/ripgrep.ts`：打包 ripgrep 后端。`resolveRgPath()` / `buildGlobCommand()` / `buildGrepCommand()` / `parseGrepJsonRecord()` / `parseGrepMatches()` / `globWithRipgrep()` / `grepWithRipgrep()` / `preferJsSearch()`。
* 新增 `RipgrepUnavailableError` 与 `clearRgPathCache()`（测试钩子）；二进制缺失时 `glob` / `grep` 透明回退，`XRK_FS_SEARCH=js` 可强制走回退遍历。
* 新增 `packages/exec/subprocess/src/capture.ts`：`StreamTailCollector`（UTF-8 尾上限 256 KiB，超顶前置 `[output truncated]`）、`appendUtf8TailCap()`、`prepareSpillBinding()`、`privateSpillDir()`、`SUBPROCESS_SPILL_MAX_BYTES`（默认 20 MiB）。
* 新增 `SubprocessResult` 的 `stdoutTruncated` / `stderrTruncated` / `stdoutSpillPath` / `stderrSpillPath`；`ShellJobInfo` 同步带上 `stdoutSpillPath` / `stderrSpillPath`（不进 Face wire）。
* 新增 shell 的 `spillDir` 选项，Host 与 harness 都指向 `{XRK_HOME}/spill`；`job_output` 文本尾部给出落盘路径。
* 新增 `fs` 的搜索导出：`FS_SEARCH_SKIP_DIR_NAMES` / `FS_SEARCH_WALK_CAP` / `FS_GREP_MAX_FILE_BYTES` / `forEachLine` / `globWalkUnderRoot` / `grepWalkUnderRoot`。
* 新增 `muxSendLaneKey()`：按 `sessionId`（含 `payload.sessionId`）分车道，`ws-send-queue` 车道内 FIFO、车道间 round-robin。
* 新增 `SessionStatusSnapshot.parentDelivery`（`turnActive` / `queued` / `steering` / `runningSubs`），壳侧 `preview-load.ts` 同步声明。
* 新增 `permission.extraWritableRoots` 到 Settings schema（`FACE_PERMISSION_SCHEMA` uid 5 → 7），base 默认 `[resolveXrkHome()]`。

### 完善

* 完善搜索后端：`glob` / `grep` 尊重 `.gitignore`，跳过 `node_modules` / `dist` / `build` / `.next` / `target` / `.venv` / `.codegraph` 等生成树；回退遍历每 48 个条目 `scheduler.yield()`，`grep` 单文件跳过 >1 MB。
* 完善工作区文件索引：`DEFAULT_FILE_SEARCH_EXCLUDED_DIRECTORIES` 从 2 项扩到 20 项（同样覆盖 `dist` / `coverage` / `Pods` 等）。
* 完善工具描述：`read_file` / `write_file` / `apply_edit` / `apply_patch` / `glob` / `grep` / `job_output` 写清绝对路径面与 ripgrep 后端。
* 完善子进程采集：每块 `pause` + `setImmediate(resume)`，并尽力把子进程降到 `PRIORITY_BELOW_NORMAL`（OCR、编译器等 CPU 密集孙进程不压过 Host）。
* 完善 job 生命周期：裁剪与 `dispose` 时删除 spill 文件（`dropJob()`），不再留孤儿。
* 完善绝对路径面：Host `hostReadableRoots` 默认产品家目录；`extraWritableRoots` 为空时回退 `{XRK_HOME}`；`readExtraWritableRoots` 同样回退，让 `bash` / `terminal_send` 的 cwd 能进家目录；Settings 条目先 `expandHomePath()`。
* 完善产品站立目录：composition 的 `productDir` 默认改为 `resolveProductHome()`，不再在**工作区根**创建 `.xrk`。
* 完善委派方 seat：子会话 Overview 的委派方球改读主会话的 turn / queue / steer / 运行中子数，并把这些接进 PresenceDock 与 PreviewTabs 的 busy 判定。
* 完善 team graph：`mergeGraph()` 在任一线路 running 时把 depth 0 的根节点点亮，不再恒为 `inactive`。
* 完善设置行响应性：`PermissionRow` 按字段分别订阅（status / writable / error / currentValue / options / extraWritableRoots）、`ExtraWritableRootsInput` 包 `memo`，`saveRoots` 改为返回 `boolean`，保存失败把输入回填。
* 完善设置行手感：`LanguageRow` / `AppearanceRow` / `EnterBehaviorRow` 的选择器补 `focus-visible` 环、按下 `scale(0.96)`、展开时 chevron 旋转，并整段尊重 `prefers-reduced-motion`。

### 修复

* 修复大仓库里 `glob` / `grep` 把生成树一起爬完、事件循环被占死：默认走 rg，回退遍历跳生成树并让出。
* 修复 `read_file` 读一个几 MB 的源文件时整份进内存、Host 卡顿：普通文本改为按 `maxBytes` 前缀读盘（Office / notebook 仍整读以便抽取）。
* 修复后台 job 刷屏时 stdout 无限增长挤爆内存：只留 256 KiB 尾，超顶落盘。
* 修复被裁剪的 job 留下 spill 孤儿文件。
* 修复一路会话的 WS 帧洪峰卡住同一 socket 上其它会话的流：按会话车道公平写出。
* 修复「等待子代理」这类在跑分支在 team graph 上把根节点渲染成「已完成」。
* 修复额外可写目录保存失败后输入框被清空、路径丢失：失败时回填草稿。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.5.13`**（接管 npm `@latest`）；npmjs 保留 **0.5.13** 与回退钉 **0.3.11**。
* Desktop 私有壳版本对齐 **0.5.13**；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。
* `@xrkseek/exec-fs` 新增依赖 `@vscode/ripgrep` 与 `@xrkseek/exec-subprocess`；`presets/harness` 新增 `@xrkseek/server-config`。
* `.gitignore` 补根目录临时物（`.scratch-opus/` · `tmp-*` · `repo.json` · `xrk-harness-promo.html`），避免本地草稿混进发版。

## 验证

* 在本仓根跑 `glob`（`**/*.ts`）/ `grep`（`resolveXrkHome`）：秒回，且结果里没有 `node_modules` / `dist`。
* `read_file` 一个 >1 MB 的文本：只返回前 `maxBytes` 并标 `truncated`；`read_file` 一个 `.docx` 仍能转出全文。
* 起一个持续吐日志的后台 `bash`，`job_output(wait:true)`：正文末尾出现 `[some output was dropped from memory; full output: …spill…]`，该路径可直接 `read_file`。
* 两个会话同时流式输出，其中一路狂刷：另一路的帧不再被压住。
* Settings → 权限：额外可写目录默认带一条 `~/.xrk`；存一条非法路径会失败并把输入回填。
* 派一个后台子代理，等它跑起来：team graph 根节点变 running，子会话 Overview 的委派方球显示主会话在跑。
* 键盘 Tab 走到语言 / 外观 / 回车行为的下拉：出现 focus 环；系统开「减少动态效果」时按下不再缩放。

### Added

* `packages/exec/fs/src/ripgrep.ts`: the packaged ripgrep backend — `resolveRgPath()`, `buildGlobCommand()`, `buildGrepCommand()`, `parseGrepJsonRecord()`, `parseGrepMatches()`, `globWithRipgrep()`, `grepWithRipgrep()`, `preferJsSearch()`.
* `RipgrepUnavailableError` and `clearRgPathCache()` (test hook). When the binary is missing `glob` / `grep` fall back transparently; `XRK_FS_SEARCH=js` forces the walk.
* `packages/exec/subprocess/src/capture.ts`: `StreamTailCollector` (256 KiB UTF-8 tail, `[output truncated]` prefix on overflow), `appendUtf8TailCap()`, `prepareSpillBinding()`, `privateSpillDir()`, `SUBPROCESS_SPILL_MAX_BYTES` (default 20 MiB).
* `SubprocessResult` gains `stdoutTruncated` / `stderrTruncated` / `stdoutSpillPath` / `stderrSpillPath`; `ShellJobInfo` carries `stdoutSpillPath` / `stderrSpillPath` (kept off the Face wire).
* Shell `spillDir` option; Host and harness both point it at `{XRK_HOME}/spill`, and `job_output` ends with the on-disk path.
* New fs search exports: `FS_SEARCH_SKIP_DIR_NAMES`, `FS_SEARCH_WALK_CAP`, `FS_GREP_MAX_FILE_BYTES`, `forEachLine`, `globWalkUnderRoot`, `grepWalkUnderRoot`.
* `muxSendLaneKey()`: lanes by `sessionId` (including `payload.sessionId`); `ws-send-queue` is FIFO within a lane and round-robin across lanes.
* `SessionStatusSnapshot.parentDelivery` (`turnActive` / `queued` / `steering` / `runningSubs`), mirrored on the shell side in `preview-load.ts`.
* `permission.extraWritableRoots` in the Settings schema (`FACE_PERMISSION_SCHEMA` uid 5 → 7) with a base of `[resolveXrkHome()]`.

### Improved

* Search backend: `glob` / `grep` honor `.gitignore` and skip `node_modules` / `dist` / `build` / `.next` / `target` / `.venv` / `.codegraph` and friends; the fallback walk yields via `scheduler.yield()` every 48 entries and `grep` skips files >1 MB.
* Workspace file index: `DEFAULT_FILE_SEARCH_EXCLUDED_DIRECTORIES` grows from 2 entries to 20 (same generated-tree coverage, plus `Pods`).
* Tool descriptions for `read_file` / `write_file` / `apply_edit` / `apply_patch` / `glob` / `grep` / `job_output` now spell out the absolute-path surface and the ripgrep backend.
* Subprocess capture: per-chunk `pause` + `setImmediate(resume)`, plus a best-effort `PRIORITY_BELOW_NORMAL` drop for the child so CPU-heavy grandchildren do not outrank the Host.
* Job lifecycle: pruning and `dispose` delete spill files (`dropJob()`) instead of orphaning them.
* Absolute-path surface: Host `hostReadableRoots` defaults to product home; an empty `extraWritableRoots` falls back to `{XRK_HOME}`; `readExtraWritableRoots` falls back the same way so `bash` / `terminal_send` cwd can enter it; Settings entries go through `expandHomePath()` first.
* Product standing directory: the composition's `productDir` defaults to `resolveProductHome()`, so `.xrk` is no longer created in the **workspace root**.
* 委派方 seat: a child Overview's parent ball reads the home session's turn / queue / steer / running-child counts, and those feed the busy checks in PresenceDock and PreviewTabs.
* Team graph: `mergeGraph()` lights the depth-0 root node when any line is running instead of pinning it to `inactive`.
* Settings rows: `PermissionRow` subscribes per field (status / writable / error / currentValue / options / extraWritableRoots) and wraps `ExtraWritableRootsInput` in `memo`; `saveRoots` now returns `boolean` and a failed save restores the typed path.
* Settings feel: the `LanguageRow` / `AppearanceRow` / `EnterBehaviorRow` selectors gain a `focus-visible` ring, a `scale(0.96)` press, a chevron rotation on expand, and respect `prefers-reduced-motion` throughout.

### Fixed

* `glob` / `grep` crawling every generated tree on a large repo and hogging the event loop: rg by default, generated trees skipped plus yields on the fallback path.
* `read_file` pulling a multi-MB source file entirely into memory and stalling the Host: plain text now reads a `maxBytes` prefix from disk (Office / notebook still read whole for extraction).
* Background jobs growing stdout without bound under a flood: 256 KiB tail, overflow to disk.
* Pruned jobs leaving orphan spill files behind.
* One session's frame burst stalling every other live stream on the same socket: fair per-session send lanes.
* A live branch rendering the team graph's root node as 「已完成」 through the missing-activity fallback.
* A failed extra-writable-roots save clearing the input and losing the path: the draft is restored.

### Other changes

* Public line target **`@xrkseek/harness-cli@0.5.13`** (owns npm `@latest`); npmjs keeps **0.5.13** and rollback pin **0.3.11**.
* Desktop private shell aligned to **0.5.13**; `apps/cli` / `apps/desktop` / `packages/sdk` versions move together.
* `@xrkseek/exec-fs` gains `@vscode/ripgrep` and `@xrkseek/exec-subprocess`; `presets/harness` gains `@xrkseek/server-config`.
* `.gitignore` covers root-level scratch (`.scratch-opus/`, `tmp-*`, `repo.json`, `xrk-harness-promo.html`) so local drafts cannot ride along with a release.

## Verify

* From the repo root run `glob` (`**/*.ts`) and `grep` (`resolveXrkHome`): both return in well under a second and neither lists `node_modules` / `dist`.

* Stream two sessions at once while one floods: the other's frames are no longer pinned behind it.
* Settings → Permission: Extra writable roots ships with a `~/.xrk` entry; saving an unusable path fails and restores what you typed.
* Spawn a background subagent and wait for it to spin up: the team graph root turns running and the child Overview's 委派方 ball shows the home session working.
