# v0.6.23

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.22](./v0.6.22.md)：**子代理并发不再互相踩死**——同一个新会话 id 被两路解析时只建一次（single-flight），设置 / MCP 变更也不再连坐杀掉正在 build 的会话；工作树租约丢了会自愈、快进受阻时可「重放后合回」。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.23`（发包后）。

Relative to [v0.6.22](./v0.6.22.md): **concurrent subagent resolution stops trampling itself** — two resolves of the same fresh session id now share one build (single-flight), and settings / MCP changes no longer cascade-dispose a session that is still materializing. Worktree leases heal themselves when a checkout vanishes, and a blocked fast-forward can be replayed. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.23` (after publish).

### 修复

* **子代理 spawn 必报 `agent scope disposed during materialize`**：这是本版头号修复。委派 spawn 的入场 drain 与预热会在同一刻解析同一个新会话 id，两条路径各自重建 scope 并互相 dispose，第一条于是炸在 `create()` 中途。现在 `resolve()` 走 single-flight，第二路直接复用同一个 build promise，不再拆正在 materialize 的 scope。新增 `isMaterializing(sessionId)` 供「能不能安全丢缓存」的判定使用。
* **设置 / MCP 变更连坐杀掉正在启动的会话**：`invalidateAll` 的跳过条件补上 `isMaterializing`，正在 build 的会话不再被 settings 命名空间变更连带回收（此前 `isBusy` 在此时仍为 false，拦不住）。
* **过程折叠「精简」档运行中看不到工具**：精简不再是「一出现就收」，改成工具运行期间展开、burst 结束再收成活动行，与「标准」同一时机。
* **收折时贴底定位跳动**：`hidden` 折叠会一次性降高度，已在夹紧底部时不再写一次 `scrollTop = scrollHeight`，避免粘性输入区被顶起来。

### 完善

* **工作树租约自愈**：租约指向的检出被手工删掉 / 分支被删时标记为 `lost`（保留 id、分支与基线提交，不再显示可点的「合回」），启动时跑一次 reconcile，并可经 `worktree.reconcile` RPC 手动对齐。
* **快进受阻给出差距**：`ff-only` 失败时同一条结果里带 `ahead` / `behind`，读的人不用再自己去数。
* **新策略 `rebase-ff`**：把子代理分支重放到主仓当前提交后再快进；rebase 冲突自动 abort，工作树与租约保留，交给人工。Status 面板在「保留中」行上给出「重放后合回」按钮。
* **模型列表 reconcile 抽出独立模块**：刷新/挑选候选时哪些行保留、哪些空字段可由上游填写、候选带过来什么，规则从组件里挪进 `model-list-sync.ts`，可无渲染单测（12 条）。
* **社区插件大资源走 gzip**：插件资产服务对 `.js/.mjs/.css/.json/.svg/.map/.txt/.html` 按 `Accept-Encoding` 压缩（office 预览约 22 MB，不压缩时经典 `<script src>` 常在解析前就报错）。

## 0.6 线收官 · 全景

按版本规则（MINOR 奇偶：奇数正式、偶数预览），**`0.6.x` 是预览线**：自 [v0.6.0](./v0.6.0.md) 收口接管 `@latest` 起，0.6.1 → 0.6.23 共 23 个补丁，**0.6 预览线在 v0.6.23 收官，接续 0.7.x 正式线**。按主题看这一线补齐了什么：

* **协作骨架**：Agent Teams 干员从 thin 升级到高级公文包（`skills` / `files` / `env_prep` + 导出导入往返 + 自编辑）；子代理默认投递 queue→steer；父会话能看到子代理「为什么停」与已做进度；名册导入、提供方重排、命令面板 frecency。
* **隔离与合回**：worktree 从「只能创建」补成全生命周期——租约 `lost` 自愈 + 启动 reconcile + `worktree.reconcile` RPC + ff-only 失败给 ahead/behind 诊断 + 新策略 `rebase-ff`（冲突自动 abort 并保留租约）。
* **并发可靠性**：修掉 agent cache 并发 resolve 竞态——两路同时 materialize 同一个新会话时互相 dispose，导致子代理必报 `agent scope disposed during materialize`；改为 single-flight 复用同一 build promise，并让 `invalidateAll` 保护 materializing 会话。
* **过程可视化**：对齐 Cursor 的过程折叠、活动摘要行、四档收起时机、折后停扫光、图片 peek。
* **模型层**：models.dev 富化、thinking 上 wire、OpenCode Zen / Go 出站会话头、真实失败原因透传、流内错误重试、单模型会话上限 + 刷新填空，pi-ai 升到 1.3.0。
* **分发与设置**：桌面包在保留根 devDeps 的前提下打包、提供方 / 模型双层 HTTP 代理、Settings 焦点与深链接。
* **上下文与记忆**：分层记忆与 curated memory、spill、归档减负。
* **工具卫生**：`todo_write` 完成纪律按需注入；web-card / 图片结果带图。

一句话：0.6 预览线把「能干活的本地 harness」补成了「能委派、能手改、能退回去」的形态——干员从能装走到能长能还，过程从一团日志变成一行摘要，并发与租约这类「偶发但致命」的缺陷在收官前补齐。

### Fixed

* **Every subagent spawn reported `agent scope disposed during materialize`** — the headline fix. The drain admit and the spawn warm-up resolve the same fresh session id at the same moment; each path rebuilt the scope, the second disposed the first mid-`create()`, and the first threw. `resolve()` is now single-flight: the second caller reuses the same build promise instead of tearing down a scope that is still materializing. New `isMaterializing(sessionId)` answers "is it safe to drop this cache yet".
* **Settings / MCP changes cascade-disposed a starting session**: `invalidateAll` now also skips `isMaterializing` sessions — `isBusy` is still false during the build window, so it could not protect them before.
* **Compact fold hid tools while the run was live**: compact no longer folds the instant the run appears; it opens while tools run and folds to the activity line when the burst settles (same point as standard).
* **Jump when folding at the bottom**: a `hidden` collapse drops height in one layout; an already-clamped scrollport no longer takes a no-op `scrollTop = scrollHeight` write that could lift the sticky composer.

### Improved

* **Worktree leases heal**: a lease whose checkout was removed by hand (or whose branch was deleted) is marked `lost` — id, branch and base commit stay for traceability, and the unusable 「合回」 button disappears. Reconcile runs at startup and on demand via `worktree.reconcile`.
* **Fast-forward failures explain themselves**: the result now carries `ahead` / `behind` next to the refusal.
* **New `rebase-ff` strategy**: replay the child branch onto the parent tip, then fast-forward. A rebase conflict is aborted, leaving the worktree and lease for a human. The Status panel offers 「Replay & merge」 on retained rows.
* **Model-list reconcile moved into its own module**: which rows a refresh keeps, which blank fields the provider may fill, what a picked candidate carries over — out of the component and into `model-list-sync.ts`, covered by 12 render-free tests.
* **Community plugin assets gzip**: `.js/.mjs/.css/.json/.svg/.map/.txt/.html` are compressed when the client sends `Accept-Encoding: gzip` (office preview ships ~22 MB, and an uncompressed classic `<script src>` often errors before parsing).

## 0.6 line close-out · the whole arc

By the version rule (MINOR parity: odd formal, even preview), **`0.6.x` is a preview line**: 23 patches (0.6.1 → 0.6.23) after [v0.6.0](./v0.6.0.md) closed it and took `@latest`, so **the 0.6 preview line ends at v0.6.23 and hands over to the 0.7.x formal line**. Themed, not a version-by-version log:

* **Collaboration skeleton**: Agent Teams grew from thin cards to advanced briefcases (`skills` / `files` / `env_prep`, export/import round-trips, self-editing); child delivery defaults to queue→steer; the parent sees *why* a child stopped and what it had already done; roster import, provider reordering, command-palette frecency.
* **Isolation and merging**: worktrees went from create-only to a full lifecycle — lease `lost` self-healing + startup reconcile + `worktree.reconcile` RPC + ahead/behind diagnostics when `ff-only` refuses + the new `rebase-ff` strategy (a conflict aborts and keeps the lease).
* **Concurrency reliability**: the agent-cache resolve race is fixed — two callers materializing the same fresh session disposed each other, so every subagent spawn reported `agent scope disposed during materialize`; it is now single-flight on one build promise, and `invalidateAll` protects materializing sessions.
* **Process visibility**: Cursor-parity process folding, the activity summary line, four-point fold timing, no shimmer after folding, image peek.
* **Model layer**: models.dev enrichment, thinking on the wire, OpenCode Zen / Go session headers, real failure causes surfaced, in-stream error retries, per-model session caps with refresh filling blanks, pi-ai on 1.3.0.
* **Distribution and settings**: desktop packaging that keeps root devDeps, layered per-provider / per-model HTTP proxies, Settings focus and deep links.
* **Context and memory**: layered memory and curated memory, spill, archive offload.
* **Tool hygiene**: `todo_write` completion discipline injected on demand; web cards and image results carry their image.

In one line: the 0.6 preview line turned “a local harness that can work” into “a harness that can delegate, be reshaped, and be rolled back” — agents went from installable to growable and returnable, a process log became one activity line, and the rare-but-fatal concurrency and lease defects were closed before the line ended.
