# v0.7.6

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

## 中文

相对 [v0.7.5](./v0.7.5.md)：表情球装扮大规模扩建（**40 形状 · 28 配色 · 12 副眼镜 · 18 顶帽子 · 11 个品牌手持**）、身体/眼睛可**任取颜色**、球尺寸三端同源可调；修掉一批「选完不生效 / 看着不对」的装扮问题，团队面板换装扮**即时热更**（不必刷新）。另：检查点快照加三道闸（实测 9 GiB → 21.7 MiB 量级）、Desktop 安装包不再塞进一整份 Electron。

### 新增

* **表情球形状 14 → 40**：新轮廓由 `apps/web/public/presence/emotion-ball/rings.js` 单一真源绘制（`polyRing` 硬边 / `puffRing` 圆并集）；拾取按钮图标改由 `scripts/gen-shape-glyphs.mjs` 从同一真源生成，不再手工维护第二套。
* **品牌手持 10 → 11 款**：微信 / QQ / 抖音 / DeepSeek / 哔哩哔哩 / GitHub / 小红书 / 淘宝 / 微博 / 知乎，新增 **`brand-xrk`（XRK-harness logo）**——取 `apps/web/public/logo-mark.svg` 的 `petal` + `accent` 两条**纯代码 path** 按 348→24 仿射缩放到 24×24（合并 bbox 中心 11.98,11.98），不依赖位图：牌底 `#1E211C`、白花瓣、金水滴 `#EAB039`。引擎 `BRANDS` 新增可选 `accent` / `accentColor` / `glyphColor`，`ball.js` 与 `canvas-ball.js` 双色绘制，选择器 `CompanionKitMark` 与三语 `team.kit.brand-xrk` 同步。
* **自定义取色（身体 / 眼睛）**：Settings 外观与干员团队面板都可给身体、眼睛各取任意颜色（原生取色器，存 `#rrggbb`）；留空 / 点「跟随预设」即回到预设色板，预设色块照常可用。
* **表情球尺寸微调 0.8–1.2（步进 0.02）**：团队面板滑杆 → Host `parseMemberBallSize` → `appearanceLookWire` → 侧栏 `companionLook` → 预览双球，三端常量同源；舞台盒子固定、只缩球本身。
* **新技能 `xrk-worktree-hygiene`**：教干员影子仓的成本模型（append-only、`gc` 收不回、只有策略 bump 能重建）与产物落点纪律——产物出树并报路径、与产物目录同轮写 `.gitignore`、明知超限要说出来；standing `AGENTS.md` 加 Catalog / Habits 各一行，不加载正文也生效。

### 完善

* **调色板 57 → 28**：四处枚举（`COMPANION_COLORS` / `PRESENCE_COLORS` / `MEMBER_COLORS` / `PRESENCE_COLOR_PALETTES`）与三语文案同步收敛。
* **眼镜 12 副重做造型**：圆金属框 / 旅行者 / 猫眼 / 飞行员 / 运动 / 椭圆 / 方框 / 半框 / 无框 / 单片 / 赛博 / 墨镜；每片走独立的 lens-L/R 锚点，随眼睛与转头（yaw）走。
* **帽子 18 款各自固有色**（不再全部由球色派生），按**弦宽**归一化（旧实现按头半宽，实物只有头宽 1/4，鸭舌读不出）；新增 bucket / beret，补齐 canvas 渲染的 beanie 分支，SVG 与 Canvas 两条渲染路径逐款对齐。
* **装扮配色随体色派生**：描边 / 镜片 / 帽檐 / 帽体 / 装饰 / 缝线由体色 HSL 相位算出，28 种体色都能自动协调；深色球（相对亮度 < 0.32）的装饰件改走固定亮色，不再发闷。
* **品牌牌统一摆版**：30×30 圆角牌按 `hw/42` 缩放、一根短杆，双色品牌（XRK 花瓣 + 金水滴）叠第二条 path；团队面板 / 侧栏 / 预览 / Canvas 用同一张牌。
* **双球渲染不再每次轮询重画**：`mergeLiveLook` 从组件 render 内提到模块级纯函数，`childMemberLook` / `parentMemberLook` 用 `useMemo` 包住——此前每次 render 都新建对象，`PresenceBall` 的 `memo` 完全失效，状态轮询一次就整球重渲染。
* **门禁**：`package.json` 新增 `gen:glyphs`；`scripts/check.mjs` 新增 `gen-shape-glyphs --check` 防漂移（改了轮廓忘了重新生成会直接红）；新增契约测试覆盖形状 40 / 颜色 28 / 帽子 18 / 眼镜 12 / 手持 24、球尺寸三端同源、glyph 与轮廓一致、轮廓锐度（star / star6 尖角比 ≥ 2.2、drop / teardrop 尖端曲率半径 < 4px）、帽款 SVG↔Canvas 对齐、折叠 rail 必须隐藏。

### 修复

* **团队面板换装扮要刷新才生效**（自定义眼镜/帽子/手持换完，概况双球不动）：live patch 只带原始 `sticker:<id>` pick，Host 仅在快照里解析成图片，而 `PresenceBall` 把 pick 当引擎 id 用 → 引擎不认识前缀就静默不画。现由 `memberSlot()` 在渲染时用 `presenceSettingsRuntime.getStickers()` 解析三槽（存储贴纸时引擎置 `none` + overlay 取图）。
* **内置帽与上一枚贴纸叠加**：`TeamRoster.nextAppearance` 随 pick 重算 `overlay*` 三槽（空串清除），换回内置装扮不再残留旧贴纸。
* **老板席装扮选完又弹回空的**：Host 侧 `presence-dressing.ts` 的 HAT / GLASSES / HELD 白名单停在旧版，`parseSlotPick` 把新 id 静默改写成 `none`（干员走自由字符串所以正常）。白名单补齐到 19 / 13 / 24。
* **新调色板的颜色选了不生效（回落 cream）**：Host `validateSettingsNamespace` 的颜色白名单只有 20 项，28 色板里有的色号被拒、球退回默认色。白名单与客户端 `COMPANION_COLORS` / `PRESENCE_COLORS` 对齐并加注释锁步。
* **低顶点形状的眼睛偏到一侧**（星形最明显）：轮廓扫描线遇到落在同一条线上的水平边时只取了 `a[0]`，丢掉右边界，眼睛被拖偏。改为同时收两侧交点。
* **star 渲染成五瓣花、teardrop 渲染成普通圆**：轮廓控制点圆化过度，尖角被抹平；重画几何并加锐度契约测试，拾取图标与引擎共用同一份轮廓。
* **贴纸眼镜整图铺在两眼中间**，一转头镜片就离开眼球：改为「半幅 ↔ 单眼」映射，左右片各跟左右眼。
* **干员团队 UI 自定义颜色不生效**（团队面板里仍是白球黑眼）：老板席 `BossSeatBall` 的 `CompanionBall` 漏传 `bodyColor` / `eyeColor` / `size`。
* **概况折叠时双球漏到面板外**并压成 1px 竖条：`.presenceRail[aria-hidden]` 缺隐藏规则，compact `.mount` 的 inset 覆盖与居中 transform 打架。
* **canvas 渲染路径补齐**（桌面老板座位预览、站点 worker）；worker 的 `importScripts` 继承 `?v=` 版本号，避免读到旧引擎缓存。
* **`parsePresenceSize` 浮点量化错误**：1.19 被算成 1.18。
* **一次 turn 快照吃掉 9 GiB**：旧排除表只有九个硬编码目录名，真实工作区一个 turn 就 9.14 GiB / 323 commits。新增三道闸——单文件 10 MiB 上限、产物后缀（压缩包 / 办公文档 / 媒体 / 编译产物）、目录名；实测 26,855 files / 9.50 GiB → **6,812 files / 21.7 MiB（-99.8%）**。超限检测只 stat 未跟踪未忽略文件（`git ls-files --others --exclude-standard`），常规 turn 只量几个路径。策略版本 bump（`SNAPSHOT_POLICY_VERSION` + `ensurePolicy`）会丢弃 shadow 仓重建——旧 blob 从 `HEAD` 可达、`gc` 永远收不回，只能重建；`/rollback` 如实报旧点已消失，不假装还在。被闸掉的文件在记录字段、列表行、restore plan/result 里**如实上报**（静默缩小还原集比占空间更糟）。
* **Desktop 安装包不再塞进一整份 Electron**：`electron` / `electron-builder` 移回 `devDependencies`，且禁止 `package:desktop` 与 `release` / `release:stage` 并行（并行会掏空根 `typescript`，并把整份 Electron 打进 `app.asar.unpacked`，exe 曾 ~330 MB）；正常包回到 **190–230 MB**。

## English

Relative to [v0.7.5](./v0.7.5.md): the emotion-ball wardrobe grows a lot (**40 shapes · 28 colors · 12 glasses · 18 hats · 11 brand props**), body/eye colors become free-form, and one size trim drives all three surfaces — plus a batch of "picked it, nothing changed" dressing fixes and live updates in the team panel (no refresh). Also: checkpoint snapshots get three gates (9 GiB → ~21.7 MiB on the measured repo), and the Desktop installer stops packing a second Electron.

### Added

* **Emotion-ball shapes 14 → 40**: the new silhouettes are drawn from one source, `apps/web/public/presence/emotion-ball/rings.js` (`polyRing` for hard edges, `puffRing` for round unions). Picker icons are generated from the same source by `scripts/gen-shape-glyphs.mjs`, so there is no hand-maintained second outline set.
* **Brand props 10 → 11**: WeChat / QQ / Douyin / DeepSeek / Bilibili / GitHub / Xiaohongshu / Taobao / Weibo / Zhihu, plus **`brand-xrk` (the XRK-harness logo)** — the `petal` + `accent` paths from `apps/web/public/logo-mark.svg`, affinely scaled 348→24 into a 24×24 box (merged bbox centre 11.98,11.98), no bitmap: badge ground `#1E211C`, white petals, gold drop `#EAB039`. The engine's `BRANDS` gains optional `accent` / `accentColor` / `glyphColor`; `ball.js` and `canvas-ball.js` draw both tones; the picker (`CompanionKitMark`) and the trilingual `team.kit.brand-xrk` key follow.
* **Free-form body / eye colors**: Settings → appearance and the agent-team panel both take any colour for body and eyes (native picker, stored as `#rrggbb`). Clearing it or hitting "follow preset" falls back to the preset palette; preset swatches keep working.
* **Ball size trim 0.8–1.2 (step 0.02)**: team-panel slider → Host `parseMemberBallSize` → `appearanceLookWire` → sidebar `companionLook` → preview balls, one set of constants across all three surfaces. The stage box stays put; only the ball scales.
* **New skill `xrk-worktree-hygiene`**: teaches the shadow-repo cost model (append-only, `gc` cannot reclaim, only a policy bump rebuilds) and artifact placement discipline — artifacts outside the tree with the path reported, `.gitignore` written in the same turn as the artifact dir, and an out-loud warning for a file knowingly left over the cap. Standing `AGENTS.md` gains one Catalog row and one Habits line so the habit is live without loading the body.

### Polished

* **Palette 57 → 28**: the four enums (`COMPANION_COLORS` / `PRESENCE_COLORS` / `MEMBER_COLORS` / `PRESENCE_COLOR_PALETTES`) and the trilingual copy converge together.
* **12 glasses rebuilt**: round metal / wayfarer / cat-eye / aviator / sport / oval / square / half-rim / rimless / monocle / cyber / shades; each lens uses its own lens-L/R anchor and follows the eyes through head yaw.
* **18 hats each get their own colours** (no longer derived from the ball), normalised by **chord width** (the old code normalised by head half-width, so a real brim came out at a quarter of the head and the peak read as nothing). Bucket / beret added, canvas beanie branch filled in, and the SVG and Canvas paths are aligned hat by hat.
* **Dressing colours derive from the body hue**: rim / lens / brim / crown / trim / seams come from the body colour's HSL phase, so all 28 body colours stay coherent; dark balls (relative luminance < 0.32) switch their trims to fixed brights instead of going muddy.
* **One badge layout**: a 30×30 rounded plate scaled by `hw/42` on a short stick; two-tone brands (XRK petals + gold drop) stack a second path. Team panel, sidebar, preview and Canvas all use the same badge.
* **The two Overview balls stop repainting on every poll**: `mergeLiveLook` moves out of the component render into a module-level pure function, and `childMemberLook` / `parentMemberLook` are wrapped in `useMemo` — previously every render built fresh objects, which defeated `PresenceBall`'s `memo` entirely and re-rendered the ball on each status poll.
* **Gates**: `package.json` gains `gen:glyphs`; `scripts/check.mjs` runs `gen-shape-glyphs --check` so a silhouette edit without regeneration fails the build. New contract tests cover 40 shapes / 28 colors / 18 hats / 12 glasses / 24 held ids, the three-surface size source, glyph↔outline parity, silhouette sharpness (star / star6 spike ratio ≥ 2.2, drop / teardrop tip curvature radius < 4px), hat SVG↔Canvas parity, and the collapsed rail staying hidden.

### Fixed

* **Dressing changes in the team panel needed a refresh** (pick custom glasses/hat/held, the Overview balls did not move): the live patch carries the raw `sticker:<id>` pick, the Host only resolves it to an image inside the snapshot, and `PresenceBall` handed the pick to the engine as an id — an unknown prefix drew nothing, silently. `memberSlot()` now resolves all three slots at render time through `presenceSettingsRuntime.getStickers()` (engine gets `none`, overlay gets the image).
* **A builtin hat stacked under the previous sticker**: `TeamRoster.nextAppearance` now recomputes the `overlay*` slots on every pick (empty string clears), so switching back to a builtin drops the old sticker.
* **The boss seat's dressing choice snapped back to empty**: the Host-side HAT / GLASSES / HELD whitelist in `presence-dressing.ts` was stale, and `parseSlotPick` silently rewrote unknown ids to `none` (roster members store free strings, which is why they were fine). Whitelists brought up to 19 / 13 / 24.
* **New palette colours were rejected (fell back to cream)**: `validateSettingsNamespace` on the Host only knew 20 colours, so some of the 28-colour palette was refused and the ball reverted to the default. The whitelist is now in lockstep with the client's `COMPANION_COLORS` / `PRESENCE_COLORS`, with a comment saying so.
* **Eyes drifted to one side on low-vertex shapes** (most visible on star): when a scanline hit a horizontal edge lying on it, only `a[0]` was taken, dropping the right bound and dragging the eyes. Both intersections are collected now.
* **`star` rendered as a five-petal flower and `teardrop` as a plain circle**: the outline control points were over-rounded and the tips were smoothed away. Geometry redrawn and pinned by a sharpness contract test; picker icons and the engine share the same outline.
* **Sticker glasses were stretched across both eyes**, so a lens left the eyeball as soon as the head turned: now mapped "half image ↔ one eye", each half following its own eye.
* **Custom colours did not apply inside the team UI** (still a white ball with black eyes): the boss seat's `BossSeatBall` did not pass `bodyColor` / `eyeColor` / `size` to `CompanionBall`.
* **The two Overview balls leaked out of the panel when collapsed** and squashed into a 1px strip: `.presenceRail[aria-hidden]` had no hiding rule, and compact `.mount`'s inset override fought the centring transform.
* **Canvas render path filled in** (Desktop boss-seat preview, site worker); the worker's `importScripts` now inherits the `?v=` revision so it cannot read a stale engine cache.
* **`parsePresenceSize` quantisation bug**: 1.19 came out as 1.18.
* **One turn's snapshot ate 9 GiB**: the old exclude list was nine hard-coded directory names, so a real workspace produced 9.14 GiB / 323 commits per turn. Three gates added — a 10 MiB per-file cap, artifact suffixes (archives / office blobs / media / compiled output) and directory names; measured 26,855 files / 9.50 GiB → **6,812 files / 21.7 MiB (-99.8%)**. Over-cap detection only stats untracked, non-ignored files (`git ls-files --others --exclude-standard`), so a normal turn measures a handful of paths. A policy-version bump (`SNAPSHOT_POLICY_VERSION` + `ensurePolicy`) discards and rebuilds the shadow repo — old blobs are reachable from `HEAD` and `gc` can never drop them, so a rebuild is the only way; `/rollback` honestly reports the old points as gone instead of pretending. Gated-out files are reported in the record field, list row, and restore plan/result — silently shrinking the restore set would be worse than the bloat.
* **The Desktop installer stopped packing a second Electron**: `electron` / `electron-builder` moved back to `devDependencies`, and `package:desktop` may not run in parallel with `release` / `release:stage` (that hollows out the root `typescript` and packs an entire Electron into `app.asar.unpacked` — the exe hit ~330 MB once). Normal installers are back to **190–230 MB**.
