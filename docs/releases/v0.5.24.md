# v0.5.24

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.5.23](./v0.5.23.md)：右键菜单在富文本编辑器里真正走编辑器自己的编辑栈（撤销 / 剪切 / 复制 / 删除），选区不再被菜单偷焦点冲掉，菜单弹出不再挤瘦外壳；技能目录截断时给出明确的下一步而不是让代理即兴发挥。

Relative to [v0.5.23](./v0.5.23.md): the context menu now drives the rich-text editor's own editing stack (undo / cut / copy / delete), the right-click selection survives the menu stealing focus, an open menu no longer squeezes the shell, and a budget-truncated skill catalog tells the agent what to do next instead of inviting improvisation.

### 修复

* 修复富文本编辑器里右键菜单的撤销 / 重做：编辑器（Lexical + `@lexical/history`）有独立于浏览器的撤销栈，菜单原先用 `execCommand` 打浏览器栈，会让这两行灰掉或动作错位。现在走编辑器监听的 `beforeinput`（`historyUndo` / `historyRedo`），编辑器撤销栈为空时与 `Ctrl+Z` 一样安全空操作。
* 修复右键选中即丢失：菜单为了键盘导航会把焦点抢到第一行，contenteditable 的选区随之消失，剪切 / 复制 / 删除拿不到用户高亮的内容。现在在右键时快照选区书签，执行动作前恢复（原生输入框记 `selectionStart/End`，contenteditable 记 `Range` 集合）。
* 修复复制 / 剪切没进系统剪贴板：菜单合成的是事件而非真实快捷键，系统剪贴板不会自动更新。现在动作结束后把编辑器写进事件的数据冲刷到系统剪贴板，失败则至少回填右键时捕获的选中文本。
* 修复右键菜单弹出时外壳被挤瘦：门户式菜单在没有流内锚点时仍会留下一段空的 `inline-flex`，它撑出的行高让 body 弹出滚动条，外壳按滚动条宽度被压缩整个菜单存续期。现在这类宿主脱离文档流（零尺寸 + `pointer-events: none`）。
* 修复删除动作不进入编辑器历史：contenteditable 删除改走 `beforeinput` 的 `deleteContentBackward`，编辑器会记录这一步；原生控件在没有 `execCommand` 时回退 `setRangeText`。

### 完善

* 完善右键菜单的选区判定：选区是否存在改由书签回答（`hasContextMenuSelection`），不再依赖菜单打开后的实时状态。
* 完善技能目录的注入文案：目录可能被预算截断，现在明确告诉代理「没匹配到就自己列 `$XRK_HOME/skills/*/SKILL.md` 与 `.agents/skills/`，别即兴发挥」，而不是让它凭记忆拼流程。
* 完善站立人格与技能路由：新增 Tools 段（先加载匹配技能再动手、任务开始建主线、多步任务写 todo、模糊匹配先用 lsp），并把「主线 / 支线」「Agent Team」的长段落收敛为指向 `xrk-thread-pin` / `xrk-delegate` 两个技能；`xrk-plan-build` 改为计划与实现的同会话流程；新增 **`xrk-thread-pin`** 技能（主线 catalog 语义）；SOUL 补上支线 caption 与装扮入口。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.5.24`**（接管 npm `@latest`）；npmjs 保留 **0.5.24** 与回退钉 **0.3.11**。
* Desktop 私有壳版本对齐 **0.5.24**；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。

---

### Fixed

* Undo / redo in a rich-text editor: the editor (Lexical + `@lexical/history`) keeps its own undo stack, so the menu’s old `execCommand` calls hit the browser stack and either greyed those rows or moved the wrong thing. Rows now fire the `beforeinput` the editor already listens for (`historyUndo` / `historyRedo`); an empty editor history no-ops exactly like `Ctrl+Z`.
* Right-click selection no longer vanishes: the menu focuses its first row for keyboard walk, which clears a contenteditable selection, so cut / copy / delete had nothing to act on. The selection is now snapshotted at right-click time (start/end for native controls, a `Range` set for contenteditable) and restored before the gesture runs.
* Copy / cut never reached the system clipboard: the menu synthesizes events rather than real shortcuts, so the OS clipboard stayed stale. Data the editor wrote onto the event is now flushed out afterwards, falling back to the text captured at right-click.
* An open context menu no longer squeezes the shell: a portaled Menu with no in-flow anchor still left an empty `inline-flex` behind, whose line box popped a body scrollbar and compressed the layout for the menu’s whole lifetime. That host is now taken out of flow (zero-size, `pointer-events: none`).
* Delete now lands in the editor’s history: contenteditable deletion goes through `beforeinput` / `deleteContentBackward`, which the editor records; native controls fall back to `setRangeText` when the command is unavailable.

### Improved

* Selection detection now answers from the bookmark (`hasContextMenuSelection`) instead of the live state after the menu opened.
* Skill-catalog injection: the catalog can be budget-truncated, and it now tells the agent that if nothing matches it should list `$XRK_HOME/skills/*/SKILL.md` and `.agents/skills/` itself rather than improvise a workflow from memory.
* Standing persona and skill routing: a new Tools section (load the fitting skill before the first write, mint a 主线 at task start, `todo_write` for multi-step work, `lsp` before guessing); the long 主线 / 支线 and Agent Team paragraphs now route to the `xrk-thread-pin` / `xrk-delegate` skills; `xrk-plan-build` is now plan-then-build in the same session; a new **`xrk-thread-pin`** skill documents the 主线 catalog; SOUL notes the 支线 caption and the dressing entry point.

### Other changes

* Public line target **`@xrkseek/harness-cli@0.5.24`** (owns npm `@latest`); npmjs keeps **0.5.24** and rollback pin **0.3.11**.
* Desktop private shell aligned to **0.5.24**; `apps/cli` / `apps/desktop` / `packages/sdk` versions move together.
