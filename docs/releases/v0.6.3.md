# v0.6.3

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.2](./v0.6.2.md)：免费通道里 HTTP 200 但流里带错误时会重试；压缩摘要走同一套重试；「已停止」会按停下来源分开写；思考流不再把整页拖慢。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.3`。

Relative to [v0.6.2](./v0.6.2.md): a free lane that returns HTTP 200 with an error inside the stream is retried; compaction summaries share that retry; Stop chrome names why the turn ended; the Think stream no longer stalls the whole page. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.3`.

### 完善

* **模型请求默认多试几次**：Settings「步内重试次数」默认从 5 提到 8（填 0 仍关闭）。压缩摘要（主动软压和上下文溢出）与本步主调用共用同一套重试，可重试失败会记进 `llm/retry`。
* **获取模型时带上软压缩预算**：新采纳、且列表披露了上下文窗口的模型，会按窗口写出 `softBudgetMaxTokens`（大窗口取 `max(100k, 75%)`，千位取整，上限 300k；小窗口按 75%；不足 8k 不写）。之后再拉取只补空白项，手填的值不动。软预算高于该模型窗口时，步前会封顶到窗口。
* **思考流跟得上日志**：流式刷新大约每 48ms 画一帧，不再按每个 token 重画整列。正在生成的思考正文只排版尾部一段；侧栏轮次预览也不再跟着每个 token 更新。
* **会话被换掉时不再写成「已停止」**：你点停止仍是「已停止」。会话被释放、父会话停掉、安全策略中止、异常中断、中断后恢复，各自有对应文案。重试详情里会带上错误码。达到输出上限时的提示会说明：自动续写用完后，再发「继续」仍可手动接着写。

### 修复

* **免费通道 HTTP 200 里的错误会重试**：OpenAI 兼容流在状态码 200 上若收到 SSE `{error}`（免密网关诱饵工具名、上游拒绝等），按可重试的服务端错误处理，不再当成空回复直接结束。
* **正在跑的会话不会被设置改动拆掉**：Host 在该会话忙时跳过因设置变更触发的整段失效，避免把进行中的回合记成用户停止。

* Desktop 更新源同步 win-x64 未签名测试包 `xrk-harness-0.6.3-win-x64.exe`。

### Improved

* **Model calls retry a few more times by default**: Settings in-step retry cap moves from 5 to 8 (`0` still disables). Compaction summaries (proactive soft budget and context overflow) share that policy with the step’s provider call; retriable failures append `llm/retry`.
* **Fetched models pick up a soft compact budget**: a newly adopted model that discloses a context window gets `softBudgetMaxTokens` from that window (large windows use `max(100k, 75%)`, stepped to 1k, cap 300k; smaller windows use 75%; under 8k stay blank). A later fetch only fills a blank value; hand-tuned numbers stay. If the soft budget sits above the route window, the loop caps it to the window before the step.
* **Think stays with the log**: stream paints about every 48ms instead of redrawing the column on every token. A live Think body lays out only a tail slice; the turn-rail preview ignores in-flight response text.
* **Releasing a session is not “Stopped”**: a click on Stop still reads Stopped. Session release, parent stop, safety-policy stop, unexpected interrupt, and recovery after interrupt each have their own line. Retry details include the error code. The output-cap notice says that after auto-continue rounds are used up, sending “continue” still resumes by hand.

### Fixed

* **Free-lane errors inside HTTP 200 are retried**: an OpenAI-compatible stream that returns SSE `{error}` on status 200 (free-lane decoy tool name, upstream refusal) is treated as a retryable server failure instead of an empty reply that ends the turn.
* **A running session is not torn down by a settings change**: while that session is busy, Host skips the full invalidate that settings edits would otherwise trigger, so an in-flight turn is not recorded as a user Stop.

### Other changes

* Public line target **`@xrkseek/harness-cli@0.6.3`** (takes over npm dist-tag **`@latest`**); `apps/cli` / `apps/desktop` / `packages/sdk` move together.
* Desktop update feed synced with the win-x64 unsigned test build `xrk-harness-0.6.3-win-x64.exe`.
* Textbook sync: `docs/configuration.md` · `docs/session-compaction.md` · `docs/tool-settlement.md`.
