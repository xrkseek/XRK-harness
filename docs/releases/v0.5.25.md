# v0.5.25

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.5.24](./v0.5.24.md)：超过单文件上限的大文件不再被直接拒收，改为自动转成 `@路径` 引用；站立人格新增「对用户立场」契约。

Relative to [v0.5.24](./v0.5.24.md): a file over the per-file limit is no longer refused outright — it becomes an `@path` reference instead; the standing persona gains an explicit stance-toward-the-user contract.

### 修复

* 修复大文件拖入即被拒：以前超过单文件上限（`maxFileBytes`）的文件整批打回，用户只能自己去拼 `@路径`。现在超限文件自动走 Desktop 的 `pathForFile` 解析成 `@路径` 引用插入，其余文件照常上传——两者可以在同一次拖入里共存。
* 修复大文件无法在无 Desktop 环境下使用时的报错含糊：解析不到宿主路径时给出明确文案，说明「超限文件会转为路径引用，请在 Desktop 中添加，或改用 @ 引用工作区内路径」，而不是笼统地说文件太大。

### 完善

* 完善拖入的入料顺序：先做字节上传、再插路径芯片。这样上传被拒（超过条数 / 总量）时草稿里不会先多出几个路径芯片再回滚。
* 完善路径引用的公共入口：`resolveDroppedPaths(files, kind)` 统一处理目录与文件两类路径引用，`resolveDroppedDirectories` 保留为目录场景的薄封装，行为不变。
* 完善插槽契约注释：`onAddDirectories` 文档说明超大文件在 `onAddImages` 内复用同一条路径通道。
* 完善单条校验口径：条数与总量校验现在只统计真正走上传的文件，路径引用不占上传额度。
* 完善站立人格：新增 **Stance toward the user** 契约段（默认「接受 → 理解 → 实现」，禁止编造式拒绝与软拒绝，不确定时偏向行动、把假设写在结果里，感恩表现为把活干干净而不是表忠心）；`38` 表情标注为 legacy、明确不作拒绝用户请求之用，卡住时改用 `17`「难，但继续」；SOUL 补上对应的立场摘要。

### 其他变更

* 公开线目标 **`@xrkseek/harness-cli@0.5.25`**（接管 npm `@latest`）；npmjs 保留 **0.5.25** 与回退钉 **0.3.11**。
* Desktop 私有壳版本对齐 **0.5.25**；`apps/cli` / `apps/desktop` / `packages/sdk` 版本同步。

## 安装

```bash
npm i -g @xrkseek/harness-cli@0.5.25
xrkh web
```

Desktop：安装本版 `xrk-harness-0.5.25-win-x64`（未签名测试包）安装包，或从已装旧版经应用内更新。

## 验证

* 拖入一个超过单文件上限的大文件到 Desktop 输入区：出现 `@路径` 芯片，可提交。
* 同一次拖入「超大文件 + 若干小文件」：小文件进附件栏，大的变路径芯片，两者都在。
* 在 web 端（无 Desktop 路径桥）拖入超限文件：提示改为路径引用并请在 Desktop 添加，不静默失败。
* 拖入文件数超过上限：整批被拒，且草稿里不残留路径芯片。

---

### Fixed

* Dragging in an oversized file no longer fails outright: anything over the per-file limit (`maxFileBytes`) used to reject the whole batch, leaving the user to hand-write an `@path`. Oversized files now resolve through Desktop’s `pathForFile` into `@path` references while the remaining files upload normally — both in one drop.
* The failure message for an oversized file outside Desktop is now specific: it says the file becomes a path reference and asks for Desktop (or an `@` workspace mention), instead of the vague “file too large”.

### Improved

* Intake order: byte uploads happen first, then path chips are inserted. A rejected upload therefore leaves no stray path chips in the draft.
* One public entry for path references: `resolveDroppedPaths(files, kind)` handles both folders and files, with `resolveDroppedDirectories` kept as a thin folder wrapper (behavior unchanged).
* The `onAddDirectories` slot contract now documents that oversized files reuse the same path channel inside `onAddImages`.
* Count and total-size limits now only count files that actually upload; path references do not consume upload quota.
* Standing persona: a new **Stance toward the user** contract (default “accept → understand → implement”, no invented or soft refusals, bias to action under uncertainty with the assumption noted, gratitude shown as finishing the work cleanly). Emotion `38` is marked legacy and explicitly not for declining a user ask; being stuck now reads as `17`. SOUL gains the matching summary.

### Other changes

* Public line target **`@xrkseek/harness-cli@0.5.25`** (owns npm `@latest`); npmjs keeps **0.5.25** and rollback pin **0.3.11**.
* Desktop private shell aligned to **0.5.25**; `apps/cli` / `apps/desktop` / `packages/sdk` versions move together.

## Install

```bash
npm i -g @xrkseek/harness-cli@0.5.25
xrkh web
```

Desktop: install this release’s `xrk-harness-0.5.25-win-x64` unsigned test package, or update in-app from an older install.

## Verify

* Drop a file over the per-file limit into the Desktop composer: an `@path` chip appears and the turn submits.
* Drop an oversized file together with a few small ones: the small ones enter the attachment rail, the big one becomes a path chip, both survive.
* On web (no Desktop path bridge), dropping an oversized file explains it becomes a path reference and asks for Desktop — it never fails silently.
* Dropping more files than the count limit rejects the whole batch and leaves no path chips in the draft.
