# v0.6.8

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.7](./v0.6.7.md)：**干员可以打包分享了**。新增高级干员包 `xrk-agent-pack`（zip 或目录：`playbook.md` + 只给子会话的 `skills/*` + `env/SETUP.md` 准备说明），`team_import pack=` 支持本机路径与聊天附件（`attachment:sha256:…`）；薄卡仍走 `team_import card=`。高级成员导入后是**未就绪**状态，需按 `envPrep` 准备再 `team_ready`——包内脚本绝不自动执行。名册区分 `thin | advanced` 两类，`scope=global|workspace` 的可见性写清并给出「找不到 id」的下一步。包内 skills 只进子会话目录，父会话看不到。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.8`（发包后）。

Relative to [v0.6.7](./v0.6.7.md): **干员 (Agent Team members) can now be packaged and shared.** A new advanced pack kind `xrk-agent-pack` (zip or directory: `playbook.md` + child-only `skills/*` + `env/SETUP.md` prep notes) imports via `team_import pack=` from a local path or a chat attachment (`attachment:sha256:…`); thin cards still use `team_import card=`. Advanced members import **not-ready** — follow `envPrep`, then `team_ready`; pack scripts never auto-run. The roster distinguishes `thin | advanced`, spells out `scope=global|workspace` visibility, and turns a missing id into a next step. Pack skills reach only the child catalog, never the parent. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.8` (after publish).

### 新增

* **高级干员包 `xrk-agent-pack`**：可分享的干员载体，zip 或目录均可。布局为 `.xrk-agent-pack`（必需根标记，缺它即判非法包）· `manifest.json`（`kind` / `name` / `role`，可选 `brief` / `inject` / `tools`）· `playbook.md`（必填，上限 20k 字符，代替 `AGENTS.md` / rules）· `skills/<id>/SKILL.md`（可选，**只进子会话目录**）· `env/SETUP.md`（可选，父侧准备说明，**永不自动执行**）。薄卡继续用名册索引里的 `xrk-agent-member` JSON；高级包落盘在 `{XRK_HOME}/agent-rosters/packs/{scope}/{id}/`，包内 skills 不写进工作区。
* **`team_import pack=`**：`pack=` 接受本机路径或 `attachment:sha256:…`（聊天拖进来的 zip 由本会话附件事件解析后读取字节）。与 `card=` 互斥，各自必填其一。导入即注册为 `kind=advanced` 且 `ready=false`。scope 缺省不同：`card=` → `workspace`，`pack=` → `global`（想只给当前画布就显式传 `scope=workspace`）。
* **`team_ready`**：父会话备齐环境后把高级成员标为就绪；`ready` 是子代理能否实际派发该成员的门。薄成员恒就绪（`kind=thin` → `ready=true`），只有高级包需要这一步。`team_ready` 与 `team_list` 一样只对父会话开放，子会话拿不到名册写入。
* **`zip-store.readZipEntries`**：从 stored zip 字节解出条目表，供包解析复用；非法 zip / 缺标记 / 超 playbook 上限各有明确拒绝路径（`notReadyPackHints` 给出下一步）。
* **附件即包入口**：协议层附件提示分流——`.zip` 附件的文本改为「若是高级干员包，用 `team_import pack=attachment:…`（导入后未就绪 → 按 envPrep 准备 → `team_ready`）」，其他文件仍是 `read_file path=attachment:…`。聊天里拖包进来即可安装，不必先落盘。
* **名册 scope 可见性**：`scope=global` 在所有工作区可见，`workspace` 仅当前画布。查询某个不在本工作区的成员 id 时，`missingMemberHint` 会指向「用 `scope=global` 重导或去那个工作区」，不再只回一句找不到。

### 完善

* **`extraSkillDirs` 注入通道**：工作区注入新增 `extraSkillDirs`，**即便 `audience=minimal` 也照样合并**这些 skill 根——干员包的 skills 因此能被子会话看到，而父会话目录完全不受影响。注入指纹（`inject-fingerprint`）把 extra 目录一并计入，包内容变化会正常触发刷新。
* **`skill-dirs` 解析重写**：`skillDirs` 与 `extraSkillDirs` 走同一 `push`/`dirExists` 路径，存在性检查移到合并阶段做，去掉「给了 skillDirs 就直接返回、忽略工作区根」的旧分支——显式目录与工作区目录现在可共存。
* **工具文案集中**：`packShareFlowHint()` 产出单行分享流程（`card=` 薄 / `pack=` 高级、scope 缺省差异、未就绪链、禁止 `team_save` 改高级 id、禁止自动执行包脚本、包 skills 仅子会话），`team_save` / `team_import` 的 description 指过去，不再各处复述。
* **`team_list` 输出更可用**：高级且未就绪的成员在 `pub` 里带 `notReadyPackHints`；列表行标注 `advanced`，让模型一眼看出谁还不能派。
* **名册存储**：`agent-roster-store` 增加 `MemberKind`（`thin | advanced`）、`ready` 字段、`memberPackDir` / `memberPackSkillsDir` 落盘位置与 `MEMBER_PLAYBOOK_MAX`；读写两侧都按 kind 归一（thin 缺 `ready` 视为 true）。
* **`xrk-delegate` 剧本跟上**：checklist 插入「分享干员：JSON → `team_import card=`；zip → `team_import pack=` → `team_list`（envPrep）→ 准备 → `team_ready` → `member_id`」，并新增 Install / ready 一行与 Pack contract 摘要（标记 / manifest / playbook ≤20k / 子会话 skills / SETUP.md / 不含记忆与外形）。

### 修复

* **高级成员不可被 `team_save` 覆写**：对 `kind=advanced` 的 id 调 `team_save` 直接拒绝并说明走 `team_import pack=`，避免半覆写状态（包内容与名册记录分家）。
* **导出/导入文件名与错误可辨**：`safeStem` 清洗成员名生成导出文件名（advanced 出 `.zip`、thin 出 `.json`）；前端 `parseMemberImportBytes` 区分来源，错误文案分成 `importDeflate`（zip 解压失败）/ `importKind`（不是本产品的包）/ `importBad`（JSON 结构不对），不再一律「导入失败」。
* **协议测例覆盖 `.zip` 附件**：`model-only-text` 补一条，钉住 zip 附件走 pack 提示、其他附件保持 `read_file` 提示。

## 验证

* 高级包导入链：拖 zip 进聊天 → `team_import pack=attachment:sha256:…` → `team_list` 看到该成员标 `advanced` 且带 `envPrep` → 按说明准备 → `team_ready` → `subagent member_id` 可派。
* 薄卡链不变：`team_import card=` 的 JSON 导入后立即可用（`ready=true`）。
* 子代理目录：派生该成员后，子会话能看到包内 `skills/*`；父会话目录里**没有**它们。
* 保护：对高级 id 调 `team_save` 被拒；包里缺 `.xrk-agent-pack` 或 `playbook.md` 超 20k 时导入报错并给下一步。
* 导出：名册里 thin 成员导出 `.json`、advanced 成员导出 `.zip`，文件名不含非法字符。

### Added

* **Advanced 干员 pack `xrk-agent-pack`**: a shareable member carrier (zip or directory). Layout: `.xrk-agent-pack` (required root marker — its absence makes the zip illegal) · `manifest.json` (`kind` / `name` / `role`, optional `brief` / `inject` / `tools`) · `playbook.md` (required, 20k cap, stands in for `AGENTS.md` / rules) · `skills/<id>/SKILL.md` (optional, **child catalog only**) · `env/SETUP.md` (optional parent prep text, **never auto-run**). Thin cards stay as `xrk-agent-member` JSON in the roster index; advanced packs materialize under `{XRK_HOME}/agent-rosters/packs/{scope}/{id}/` and never write into the workspace.
* **`team_import pack=`**: accepts a local path or `attachment:sha256:…` (a zip dragged into chat is resolved through this session's attachment events and read as bytes). Mutually exclusive with `card=`. Import registers `kind=advanced` with `ready=false`. Scope defaults differ: `card=` → `workspace`, `pack=` → `global` (pass `scope=workspace` for a canvas-only member).
* **`team_ready`**: marks an advanced member ready once the parent has prepared the environment; `ready` gates whether the child can actually be dispatched. Thin members are always ready (`kind=thin` → `ready=true`); only advanced packs need the step. Both `team_ready` and `team_list` stay parent-only.
* **`zip-store.readZipEntries`**: reads an entry table from stored zip bytes so pack parsing can reuse it; illegal zips, missing markers and oversize playbooks each have an explicit rejection path (`notReadyPackHints` names the next move).
* **Attachments as an install entry point**: the protocol attachment hint now branches — a `.zip` attachment reads "if this is an advanced 干员 pack, use `team_import pack=attachment:…` (then envPrep → `team_ready`)", everything else keeps `read_file path=attachment:…`. Drag the pack into chat; no manual unzip.
* **Roster scope visibility**: `scope=global` shows in every workspace, `workspace` only in the current canvas. Querying an id that lives elsewhere now returns `missingMemberHint` ("re-import with `scope=global`, or open that workspace") instead of a bare "not found".

### Improved

* **`extraSkillDirs` injection channel**: workspace inject gained `extraSkillDirs`, merged **even under `audience=minimal`** — pack skills reach the child while the parent catalog stays untouched. The inject fingerprint counts the extra dirs, so pack changes refresh normally.
* **`skill-dirs` resolution rewrite**: `skillDirs` and `extraSkillDirs` share one `push`/`dirExists` path with existence checked at merge time, dropping the old "explicit dirs return early and ignore the workspace root" branch — both can now coexist.
* **Consolidated tool copy**: `packShareFlowHint()` emits one line covering thin vs advanced, scope defaults, the not-ready chain, and the bans (no `team_save` on advanced ids, no auto-running pack scripts, pack skills child-only); `team_save` / `team_import` descriptions point at it instead of re-lecturing.
* **More useful `team_list`**: advanced not-ready members carry `notReadyPackHints` in `pub`, and rows are labeled `advanced` so the model sees at a glance who cannot be dispatched.
* **Roster storage**: `agent-roster-store` adds `MemberKind` (`thin | advanced`), `ready`, `memberPackDir` / `memberPackSkillsDir` locations and `MEMBER_PLAYBOOK_MAX`; both read and write normalize by kind (thin without `ready` means true).
* **`xrk-delegate` playbook updated**: the checklist gains the sharing route (JSON → `team_import card=`; zip → `team_import pack=` → `team_list` envPrep → prep → `team_ready` → `member_id`) plus an Install / ready row and a Pack contract summary (marker / manifest / ≤20k playbook / child-only skills / SETUP.md / no memory or appearance).

### Fixed

* **Advanced members cannot be overwritten by `team_save`**: calling `team_save` on a `kind=advanced` id is refused with a pointer to `team_import pack=`, preventing half-written state where pack content and roster record diverge.
* **Export names and import errors are distinguishable**: `safeStem` sanitizes the member name for the download file (advanced → `.zip`, thin → `.json`); the client's `parseMemberImportBytes` reports the source and errors split into `importDeflate` (zip failed to expand) / `importKind` (not an XRK pack) / `importBad` (JSON shape wrong) instead of one generic failure.
* **`.zip` attachments are covered by a protocol test**: `model-only-text` pins that zips take the pack hint and other files keep the `read_file` hint.

## Verify

* Advanced install chain: drag a zip into chat → `team_import pack=attachment:sha256:…` → `team_list` shows it as `advanced` with `envPrep` → prepare per the notes → `team_ready` → `subagent member_id` dispatches.
* Thin chain unchanged: `team_import card=` JSON is usable immediately (`ready=true`).
* Child catalog: the dispatched child sees the pack's `skills/*`; the parent catalog does not.
* Guards: `team_save` on an advanced id is refused; a pack missing `.xrk-agent-pack` or with an oversize playbook fails with a next step.
* Export: thin members export `.json`, advanced members `.zip`, with filesystem-safe filenames.
