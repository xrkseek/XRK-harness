# v0.4.10

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.4.9](./v0.4.9.md)：修复全局安装 `xrkh web` 因 `@xrkseek/xrk-workflow` 入口指向 `src/*.ts`，Node 在 `node_modules` 下拒绝剥类型而启动失败。

Relative to [v0.4.9](./v0.4.9.md): fix global `xrkh web` crash when `@xrkseek/xrk-workflow` resolved to `src/*.ts` (Node refuses type-stripping under `node_modules`).

### 修复

* 修复 `@xrkseek/xrk-workflow` 包入口改回编译后的 `lib/types/index.js`（不再默认导出 `src/index.ts`）。
* 修复 Host Isolating WorkflowEngine 挂载改为动态导入；CLI 安装缺 Cordis stub peer 时软跳过，不再拖垮 `xrkh web` 启动。

### 其他变更

* 公开线 `@xrkseek/harness-cli@0.4.10`（热修；接管 `@latest`）。

## 安装

```bash
npm i -g @xrkseek/harness-cli@0.4.10
xrkh web
```

## 验证

* 全局安装后 `xrkh web` 能起来（不再报 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`）。

---

### Fixed

* `@xrkseek/xrk-workflow` package entry points at compiled `lib/types/index.js` again (no default `src/index.ts` export).
* Host Isolating WorkflowEngine mount uses dynamic import and soft-skips when Cordis stub peers are absent — `xrkh web` no longer fails to boot.

### Other changes

* Public line `@xrkseek/harness-cli@0.4.10` (hotfix; takes `@latest`).

## Install

```bash
npm i -g @xrkseek/harness-cli@0.4.10
xrkh web
```

## Verify

* After a global install, `xrkh web` starts (no `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`).
