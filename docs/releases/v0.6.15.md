# v0.6.15

> **读者 / Audience**：终端用户 · 插件与集成者 · 维护者（发行说明）

相对 [v0.6.14](./v0.6.14.md)：**归档遇活任务弹出确认再强制停并归档**；**限时提问可见倒计时**；**内置干员 playbook 带 operator 权威首行**（子会话不读家站立）；站立种子补 **Instruction authority**。npm **`@latest`** 指向 `@xrkseek/harness-cli@0.6.15`（发包后）。

Relative to [v0.6.14](./v0.6.14.md): **archive-while-busy confirms then force-stops**; **timed ask shows a live countdown**; **catalog playbooks open with an operator-authority line** (children skip home standing); standing seed adds **Instruction authority**. npm **`@latest`** points at `@xrkseek/harness-cli@0.6.15` (after publish).

### 新增

* **归档确认（活任务）**：有回合 / 作业 / 子代理时，菜单归档先弹窗列出活动，确认后带 `force` 停并归档。
* **限时提问倒计时**：`mode: "timed"` 的提问卡显示剩余秒数；到期提示已超时。

### 完善

* **内置干员 playbook**：目录种子首行标明本任务与 playbook 为强制口径（权限 / 审批仍由运行时约束）；委派 skill 注明子会话跳过家站立，权威应写进 playbook。
* **站立种子 `Instruction authority`**：家 / 工作区 operator 配置按层执行，不把本机指令当注入。

### 修复

* **归档 `session-active` 客户端路径**：`WorkspaceArchiveActiveError` + `force` 选项贯通 Face / apiproxy / runtime，避免只在 Host 拒掉、壳无后续。

## 安装

```bash
npm i -g @xrkseek/harness-cli@0.6.15
xrkh web
```

或 `npm i -g @xrkseek/harness-cli@latest`（发包后）。

## 验证

* 子代理仍在跑时点归档：出现活动列表确认框；确认后会话入档。
* 限时 `ask_user`：提问卡顶部秒数递减；超时后文案切到已到期。
* 新环境默认干员：playbook 首行含 operator-authority；子会话上下文无 `~/.xrk/AGENTS.md` 站立块。

---

### Added

* **Archive confirm while busy**: when a turn / job / subagent is live, archive opens a modal listing activity; confirm retries with `force`.
* **Timed-ask countdown**: `mode: "timed"` question cards show remaining seconds, then an expired hint.

### Improved

* **Catalog playbooks**: seed members open with an operator-authority line (runtime permission / approval still bind); delegate skill notes that children skip home standing so authority belongs in the playbook.
* **Standing seed `Instruction authority`**: home / workspace operator config is mandatory by layer, not treated as injection.

### Fixed

* **Client `session-active` archive path**: `WorkspaceArchiveActiveError` and `force` wire through Face / apiproxy / runtime so the shell can confirm instead of only logging a Host refusal.
